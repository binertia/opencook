# TASK-0050: Implement User Management and Invitation Flow

## Objective
Build the user management page with member listing, role changes, and email invitation flow.

## Context
Organization owners and admins can invite users, assign roles, and remove members. See API_SPEC.md section 3.3 and EPICS.md Epic-09.

## Acceptance Criteria
- [ ] `frontend/src/pages/settings/UsersPage.tsx` — user management
  - Table listing all org members: name, email, role, last login, status
  - Role change dropdown (owner/admin/member/viewer) — RBAC enforced
  - Remove member button with confirmation dialog
  - Status filter: All, Active, Pending, Suspended
- [ ] `frontend/src/components/users/InviteUserModal.tsx` — invitation modal
  - Email input, role selector
  - Send invitation → POST /api/v1/organizations/{org_id}/invite
  - Show success/error feedback
- [ ] `frontend/src/hooks/useUsers.ts` — users data hook
  - `useUsers(org_id)` → list users
  - `inviteUser(data)` → send invitation
  - `updateRole(user_id, role)` → change role
  - `removeUser(user_id)` → remove member
- [ ] Only owner can assign owner role or remove owner
- [ ] Admin cannot remove owner
- [ ] Audit log: role changes and removals logged

## Files Affected
- `frontend/src/pages/settings/UsersPage.tsx` — new
- `frontend/src/components/users/InviteUserModal.tsx` — new
- `frontend/src/hooks/useUsers.ts` — new

## Dependencies
- TASK-0048 (dashboard layout)

## Technical Notes
- Use shadcn/ui `Table`, `Dialog`, `Select` components
- Role change: dropdown in table row, immediate update with optimistic UI
- Remove: confirmation dialog with member name
- Pagination: server-side with limit/offset
- Search: by email or name (client-side or server-side)
- Invitation: generates link, sends email (backend handles)

## Test Requirements
- User table renders with correct columns
- Role change dropdown shows allowed roles based on current user role
- Owner can change any role; admin cannot set owner
- Remove shows confirmation dialog
- Invite modal validates email format
