# TASK-0018: Implement Key Revocation and Cache Invalidation

## Objective
Build immediate API key revocation with Redis cache invalidation and pub/sub event propagation.

## Context
Key revocation must propagate within 100ms. This requires deleting the cached key entry from Redis and publishing an invalidation event. See AUTH.md section 2.5 and EPICS.md Epic-03.

## Acceptance Criteria
- [x] `DELETE /v1/api-keys/{key_id}` revokes key (sets status='revoked')
- [x] Revocation immediately deletes Redis cache entry `auth:apikey:{key_hash}`
- [x] Publishes `apikey:revoked` event to Redis pub/sub with `{ key_hash, key_id, timestamp }`
- [x] Any request in flight with the revoked key fails within 100ms (cache miss → DB lookup sees revoked status)
- [x] Audit log entry created: action=`api_key.revoked`, with actor_id and timestamp
- [x] Revoked keys appear in list with status filterable
- [x] Cannot revoke an already-revoked key (returns 409)

## Technical Notes
- Redis cache key: `auth:apikey:{sha256(key)}` with 5-minute TTL
- On cache miss, API key is fetched from DB and cached
- On revocation (PUT status=revoked or DELETE), cache entry is deleted immediately
- Pub/sub channel `apikey:revoked` broadcasts `{ key_hash, key_id, timestamp }` for multi-instance invalidation
- The `update_api_key` endpoint also invalidates cache when status changes to revoked/inactive
- `delete_api_key` now returns 409 if key is already revoked, and uses `ApiKeyRevoked` audit action

## Security & Edge Cases Handled
1. **Cache poisoning prevention**: Cached entries include the full ApiKey record; revoked keys are never cached because they're invalidated before any new cache write
2. **Double-revocation prevention**: Both `PUT` (status=revoked) and `DELETE` return 409 if key already revoked
3. **Defense in depth**: Even if cache stale-hit occurs, constant-time hash verification still runs
4. **Pub/sub for multi-instance**: In a horizontally scaled deployment, all instances receive revocation events
5. **Audit trail**: Every revocation is logged with old/new values and actor context
