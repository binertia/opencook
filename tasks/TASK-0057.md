# TASK-0057: Implement API Key Creation with One-Time Display

## Objective
Build the API key creation form with scopes, rate limits, expiration, and the one-time full key display.

## Context
Creating an API key is a critical security action. The full key is shown exactly once and never again. See EPICS.md Epic-11.

## Acceptance Criteria
- [x] `frontend/src/components/keys/CreateKeyModal.tsx` — creation modal
  - Name input (required, 1-128 chars)
  - Scopes multi-select: chat:write, embeddings:write, models:read, usage:read
  - Rate limits: requests/second input
  - Expiration date picker (optional)
  - Submit → POST /v1/api-keys
- [x] `frontend/src/components/keys/KeyDisplayModal.tsx` — one-time display
  - Shows full key with copy-to-clipboard button
  - Warning: "This key will never be shown again"
  - Download as file option
  - Closes after copy or manual dismiss
- [x] Form validation:
  - Name required, max 128 chars
  - At least one scope selected
  - Rate limits: positive integers
  - Expiration: future date if provided

## Files Affected
- `frontend/src/components/keys/CreateKeyModal.tsx` — new
- `frontend/src/components/keys/KeyDisplayModal.tsx` — new
- `frontend/src/pages/ApiKeys.tsx` — updated to use modals

## Dependencies
- TASK-0056 (key list page)
- TASK-0047 (API client)

## Technical Notes
- Uses shadcn/ui `Dialog`, `Input`, `Label`, `Button`
- Uses `navigator.clipboard.writeText` for copy
- Key display: monospace font, highlighted in warning box
- After display modal closes: invalidates key list query to show new key
- Never stores full key in React state after modal closes
- Uses `react-hook-form` + `zodResolver` for validation
- Scope selection uses toggle buttons (better UX than native multi-select)
