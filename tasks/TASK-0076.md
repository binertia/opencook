# TASK-0076: Implement Webhook Delivery Retry UI

## Objective
Build the delivery retry functionality in the admin UI, allowing manual retry of failed webhook deliveries.

## Context
Failed deliveries can be manually retried from the dashboard. Admins need visibility into why deliveries failed. See EPICS.md Epic-15.

## Acceptance Criteria
- [x] Retry button on each failed delivery row
  - Sends POST to backend to retry specific delivery
  - Shows loading state during retry
  - Updates status on success/failure
- [ ] Bulk retry: select multiple failed deliveries, retry all
  - Checkbox selection on each row
  - "Retry Selected" button
  - **Blocked**: backend bulk retry endpoint not yet implemented
- [x] Delivery detail view (modal with tabs):
  - Full request: headers, body
  - Full response: status code, headers, body preview
  - Error reason shown in overview tab
  - Attempt timestamps and durations
- [x] Filter deliveries: All, Successful, Failed
- [x] Search by event type
- [ ] Search by trace ID — blocked: trace_id not yet stored on delivery records

## Files Affected
- `frontend/src/components/webhooks/WebhookDeliveryLog.tsx` — updated with retry, detail modal, filter, search
- `frontend/src/hooks/useWebhooks.ts` — extended `WebhookDelivery` interface with request/response fields
- `crates/gateway-api/src/routes/webhooks.rs` — extended `WebhookDeliveryItem` with request/response/payload fields

## Dependencies
- TASK-0075 (webhook management UI)

## Technical Notes
- Retry: `POST /api/v1/organizations/{org_id}/webhooks/{id}/deliveries/{delivery_id}/retry`
- Bulk retry: `POST /api/v1/organizations/{org_id}/webhooks/{id}/deliveries/retry` with body `{ delivery_ids: [...] }`
- Use shadcn/ui `DataTable` with row selection
- Delivery detail: use `Dialog` with tabs (Request, Response, Timeline)
- Use `lucide-react` icons for status indicators

## Test Requirements
- Retry button triggers retry API call
- Delivery detail shows correct request/response
- Bulk retry sends correct request
- Filter by status works correctly
