# TASK-0095: Implement Multi-Organization Support and Org Switching

## Objective
Build the backend and frontend support for users belonging to multiple organizations with organization switching.

## Context
Users may be members of multiple organizations (e.g., work and personal). The gateway must support org switching and isolated data per organization. See EPICS.md Epic-20.

## Acceptance Criteria
- [ ] `user_organizations` junction table (new migration):
  - `user_id`, `org_id`, `role`, `joined_at`, `created_by`
  - Unique constraint on `(user_id, org_id)`
  - Soft-delete not needed (remove row on leave)
- [ ] Backend: user can belong to multiple organizations
  - `GET /api/v1/auth/me` returns list of organizations with roles
  - `POST /api/v1/auth/switch-org` switches active organization
  - Active org stored in JWT claim: `active_org_id`
  - All API calls scoped to active org
- [ ] Frontend: org switcher in header
  - Dropdown showing all user's organizations
  - Click to switch (refreshes page with new org context)
  - Current org highlighted
- [ ] Org creation:
  - `POST /api/v1/organizations` — create new organization
  - Creator becomes owner automatically
  - Can invite users immediately
- [ ] Org isolation enforced:
  - All data queries include active org_id
  - Cross-org access returns 403
  - Cache keys include org_id prefix

## Technical Notes
- Junction table: no soft-delete (hard delete on leave org)
- JWT claim: `active_org_id` set on switch, re-issued token
- Frontend: store active org in Zustand store, persist in localStorage
- On switch: invalidate all TanStack Query caches
- Org creation: transaction (INSERT org + INSERT user_organizations + INSERT audit)
