# TASK-0080: Build Admin Dashboard Grafana Export

## Objective
Create Grafana dashboard JSON definitions for infrastructure monitoring (if Grafana available) or provide equivalent dashboard documentation.

## Context
Prometheus metrics need visualization. Grafana is the standard tool. For environments without Grafana, provide documentation. See ARCHITECTURE.md section 6.2 and EPICS.md Epic-16.

## Acceptance Criteria
- [ ] `monitoring/grafana/dashboard-gateway.json` — Grafana dashboard
  - Row 1: Request Overview — RPS, error rate, latency (p50/p90/p99)
  - Row 2: Cache Performance — hit rate, hit by layer, cost saved
  - Row 3: Provider Health — status per provider, latency per provider, error rate
  - Row 4: Token Usage — input/output tokens, tokens by model
  - Row 5: Quotas — quota usage percentage, exceeded count
  - Row 6: System — active connections, memory, CPU (if node_exporter available)
- [ ] Dashboard variables: org_id (optional), time range
- [ ] Alert rules: error rate > 5% for 5 min, p99 latency > 10s for 5 min, provider unhealthy > 5 min
- [ ] `monitoring/grafana/README.md` — setup instructions
- [ ] Dashboard uses Prometheus as data source

## Files Affected
- `monitoring/grafana/dashboard-gateway.json` — new
- `monitoring/grafana/alerts.yml` — alert rules
- `monitoring/grafana/README.md` — documentation

## Dependencies
- TASK-0078 (Prometheus metrics)

## Technical Notes
- Grafana dashboard JSON: use version 10+ format
- Panels: use `timeseries` for time-based data, `stat` for current values, `table` for lists
- Alert rules: use Grafana alert format or Prometheus AlertManager rules
- Color thresholds: green < 1% error, yellow 1-5%, red > 5%
- Export/import tested with Grafana 10.x

## Test Requirements
- Dashboard JSON is valid (can be imported to Grafana)
- All panels reference correct Prometheus metric names
- Alert rules have correct conditions
