# TASK-0081: Implement Request Timing Middleware and Error Reporting

## Objective
Add HTTP request timing middleware and structured error reporting with trace IDs for every request.

## Context
Request timing and error tracking are essential for debugging and performance monitoring. Every request gets a unique trace ID. See ARCHITECTURE.md section 6.1 and EPICS.md Epic-16.

## Acceptance Criteria
- [ ] Request timing middleware in `crates/gateway-api/src/middleware/timing.rs`
  - Records: request_start, gateway_processing_time, provider_latency, total_latency
  - Adds `X-Request-Time-Ms` header to response
  - Adds `X-Gateway-Request-ID` header (UUID v7)
- [ ] Error reporting middleware:
  - Catches all errors, returns structured JSON
  - Client gets: `{ error: { code, message, type, request_id } }` (no internal details)
  - Internal log gets: full error with stack trace (if available) and trace ID
- [ ] `X-Gateway-Request-ID` header on every response (success and error)
  - Generated at request start, propagated through all spans
- [ ] Timing breakdown in request log:
  - `latency_gateway_ms` — time from request start to provider call
  - `latency_provider_ms` — time provider spent processing
  - `latency_total_ms` — total request time
- [ ] Error categorization:
  - `authentication_error`, `rate_limit_exceeded`, `quota_exceeded`, `model_not_found`, `provider_error`, `gateway_error`

## Files Affected
- `crates/gateway-api/src/middleware/timing.rs` — timing middleware
- `crates/gateway-api/src/middleware/error_handler.rs` — error handling
- `crates/gateway-api/src/middleware/mod.rs` — module declarations
- `crates/gateway-api/src/router.rs` — register middleware

## Dependencies

- TASK-0077 (tracing setup)

## Technical Notes
- Use `std::time::Instant` for timing measurements
- Use `tower_http::trace::TraceLayer` for request ID generation
- Error middleware: catch `Result::Err` from handlers, format consistently
- Use `uuid::Uuid::now_v7()` for request IDs (time-sortable)
- Timing headers: `X-Gateway-Latency-Ms`, `X-Provider-Latency-Ms`, `X-Total-Latency-Ms`
- Use `tracing::error!` for 5xx errors, `tracing::warn!` for 4xx

## Test Requirements
- Integration test: success response includes timing headers
- Integration test: error response includes trace ID and error code
- Integration test: internal errors not exposed to client
- Unit test: timing middleware records correct durations
