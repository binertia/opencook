# TASK-0027: Implement POST /v1/chat/completions Endpoint (Non-Streaming)

## Objective
Build the primary LLM API endpoint for non-streaming chat completions with full OpenAI request/response compatibility.

## Context
The core gateway endpoint. Accepts OpenAI-compatible JSON, authenticates via API key, proxies to configured provider, and returns OpenAI-compatible response with gateway metadata headers. See API_SPEC.md section 2.1 and ARCHITECTURE.md section 4.1.

## Acceptance Criteria
- [ ] `POST /v1/chat/completions` handler in `crates/gateway-api/src/routes/chat.rs`
- [ ] Request body deserialized into `ChatCompletionRequest` (all OpenAI fields supported)
- [ ] Auth via API key middleware (org context attached)
- [ ] Provider selected by requested model name (from model registry)
- [ ] Request forwarded to provider adapter, response transformed to OpenAI format
- [ ] Response includes gateway headers: `X-Gateway-Request-ID`, `X-Gateway-Version`
- [ ] Response logged to `requests` table with metadata (tokens, cost, latency, provider)
- [ ] Error responses follow gateway envelope format: `{ error: { code, message, type, param, status, request_id } }`
- [ ] Drop-in replacement validated: changing base URL in OpenAI Python SDK works

## Files Affected
- `crates/gateway-api/src/routes/chat.rs` — chat completion handler
- `crates/gateway-api/src/routes/mod.rs` — route module declarations
- `crates/gateway-api/src/extractors.rs` — request payload extractors
- `crates/gateway-core/src/orchestrator.rs` — request orchestration logic

## Dependencies
- TASK-0026 (Axum server with middleware)
- TASK-0021 (OpenAI adapter)
- TASK-0024 (model registry for provider selection by model)
- TASK-0015 (API key validation)

## Technical Notes
- Use `axum::Json<ChatCompletionRequest>` extractor
- Orchestrator pattern: handler calls core orchestrator which coordinates adapter call
- Log request asynchronously (fire-and-forget bounded channel)
- Calculate cost from provider_model pricing and actual token usage
- Use `serde_json` for request/response serialization
- Handle provider errors: map to gateway error envelope with appropriate HTTP status

## Test Requirements
- Integration test: valid request returns 200 with OpenAI-compatible response
- Integration test: invalid API key returns 401
- Integration test: invalid model returns 404 model_not_found
- Integration test: response headers include X-Gateway-Request-ID
- Integration test: request logged to DB with correct metadata
- Integration test: OpenAI Python SDK works with gateway base URL (mock provider test)
