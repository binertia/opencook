# TASK-0084: Implement Audit Log System

## Objective
Build the immutable audit log that records all security-relevant actions with actor attribution and tamper-proof design.

## Context
Audit logs are append-only records of security-relevant actions. They cannot be modified or deleted. See DATABASE.md section 2.15 and EPICS.md Epic-17.

## Acceptance Criteria
- [ ] `crates/gateway-db/src/repos/audit_repo.rs` — audit log repository
  - `record(action, actor_id, org_id, resource_type, resource_id, details)` — inserts audit entry
  - `list(org_id, filters) -> Vec<AuditEntry>` — query with filtering
  - No update or delete methods (immutable)
- [ ] Audit log table (`audit_log`) has NO `updated_at` column
  - Insert-only: no UPDATE or DELETE operations allowed
  - Partitioned by created_at (monthly)
  - 90-day retention, archived to S3 after (configurable)
- [ ] Tracked actions:
  - `api_key.created`, `api_key.revoked`
  - `provider.created`, `provider.updated`, `provider.deleted`
  - `routing_rule.created`, `routing_rule.updated`
  - `quota.exceeded`, `quota.warning`
  - `webhook.created`, `webhook.deleted`
  - `settings.updated`, `billing.updated`
  - `login`, `logout`, `user.role_changed`
  - `security.violation` (cross-org access attempts)
- [ ] `GET /api/v1/organizations/{org_id}/audit-log` — paginated audit log
  - Filters: action, actor, date range, resource type
- [ ] Admin API with RBAC (owner/admin only)

## Files Affected
- `crates/gateway-db/src/repos/audit_repo.rs` — new
- `crates/gateway-api/src/routes/audit.rs` — audit log endpoint
- `crates/gateway-db/src/models.rs` — AuditEntry, AuditAction types

## Dependencies
- TASK-0010 (audit_log table migration)
- TASK-0016 (RBAC for access control)

## Technical Notes
- No `updated_at` trigger on audit_log (immutable)
- Partitioning: monthly, auto-create next month
- Retention: 90 days, then archive (S3 integration deferred)
- Use `INSERT ONLY` — no application-level update/delete
- Details stored as JSONB for flexibility
- Actor ID from AuthContext (user_id or key_id)

## Test Requirements
- Unit test: audit entry created on key revocation
- Unit test: audit entry created on provider update
- Integration test: audit log endpoint returns entries
- Integration test: cross-org access attempt logged as security.violation
- Integration test: no update/delete methods on audit repo
