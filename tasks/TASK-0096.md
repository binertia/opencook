# TASK-0096: Implement SAML 2.0 and OIDC SSO Integration

## Objective
Build SAML 2.0 and OpenID Connect (OIDC) SSO integration for enterprise authentication.

## Context
Enterprise customers require SSO via their identity providers (Okta, Azure AD, Google Workspace). Supports both SAML 2.0 and OIDC. See EPICS.md Epic-20.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/sso/saml.rs` — SAML 2.0 integration
  - `SamlProvider` struct with SP-initiated SSO
  - ACS endpoint: `POST /api/v1/auth/saml/acs`
  - SAMLRequest generation, SAMLResponse parsing
  - NameID extraction for user identity
  - Supports IDP metadata XML import
- [ ] `crates/gateway-auth/src/sso/oidc.rs` — OIDC integration
  - `OidcProvider` struct
  - Authorization endpoint redirect: `GET /api/v1/auth/oidc/authorize`
  - Callback: `GET /api/v1/auth/oidc/callback`
  - Token exchange and userinfo retrieval
  - ID token validation (signature, expiry, issuer, audience)
- [ ] SSO configuration per organization:
  - `sso_configs` table: org_id, provider_type (saml/oidc), metadata_url, entity_id, certificate
  - Admin API: `GET/POST/PUT/DELETE /api/v1/organizations/{org_id}/sso`
  - Certificate and metadata stored encrypted
- [ ] Auto-provisioning:
  - New SSO users automatically created in org
  - Role mapping from SAML attributes / OIDC claims
  - First SSO user for org becomes owner
- [ ] `GET /api/v1/auth/sso/providers` — public endpoint listing configured SSO providers

## Files Affected
- `crates/gateway-auth/src/sso/saml.rs` — SAML implementation
- `crates/gateway-auth/src/sso/oidc.rs` — OIDC implementation

- `migrations/0025_create_sso_configs.sql` — SSO config table

## Dependencies
- TASK-0095 (multi-organization support)
- TASK-0013 (JWT session auth for post-SSO session)

## Technical Notes
- SAML: use `samael` crate for Rust SAML implementation
- OIDC: use `openidconnect` crate
- IDP metadata: fetched from metadata_url on config save, cached in memory
- Certificate validation: verify IDP certificate against trusted CAs
- Auto-provisioning: create user if email not found, link to org
- Role mapping: configure attribute name for role (default: "role")
- SSO bypass: local login still available as fallback

## Test Requirements
- Unit test: SAML Response parsing extracts correct NameID
- Unit test: OIDC ID token validation succeeds/fails appropriately
- Integration test: SSO login flow (mock IDP) creates session
- Integration test: auto-provisioning creates user on first SSO login
- Integration test: role mapping assigns correct role from SSO attributes
