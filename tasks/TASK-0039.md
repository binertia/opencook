# TASK-0039: Integrate Cache into Request Orchestrator

## Objective
Integrate the two-tier cache into the request lifecycle so that cacheable requests are checked before provider calls and responses are stored after successful completion.

## Context
Cache integration is step 5 (check) and step 10 (store) of the request lifecycle. Cache hits skip the provider call entirely. See ARCHITECTURE.md sections 4.1 steps 5, 10 and EPICS.md Epic-07.

## Acceptance Criteria
- [ ] Orchestrator updated in `gateway-core/src/orchestrator.rs`:
  - Step 5: Check cache before provider call (L1 → L2)
  - Step 10: Store response in cache after successful response
  - Cache hit: return cached response with `X-Cache: HIT`, skip provider
  - Cache miss: continue to provider, store result after
- [ ] Cache hit still logs to `requests` table with `cache_hit=true` and `cost=0`
- [ ] Streaming requests bypass cache by default (unless `X-Cache-Stream: true`)
- [ ] Temperature > 0 requests bypass cache (read and write)
- [ ] PII-containing requests skip cache
- [ ] Cache store only for successful responses (2xx)
- [ ] Cache errors non-fatal: logged, request continues

## Technical Notes
- Cache check: `if let Some(cached) = cache.get(cache_key).await { return cached; }`
- Cache store: `cache.insert(cache_key, response, ttl).await` (fire-and-forget)
- Log cache hit as a request with `cache_hit=true` and zero cost
- Use `tokio::spawn` for cache store to avoid blocking response
- Header `X-Cache-TTL` overrides default TTL for this request
- On cache hit: still apply quota deduction (count as 0-cost request)
