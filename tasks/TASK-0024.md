# TASK-0024: Implement Model Registry with Pricing and Capabilities

## Objective
Build the model registry that tracks available models per provider with pricing, capabilities (streaming, tools, vision), and aliases.

## Context
The model registry enables routing decisions and cost tracking. Each provider_model entry defines a model's availability, cost, and features. See DATABASE.md section 2.5 and EPICS.md Epic-04.

## Acceptance Criteria
- [ ] `crates/gateway-db/src/repos/model_registry.rs` — model registry queries
  - `list_models(org_id) -> Vec<ModelEntry>` — all active models for org
  - `get_model(org_id, model_id) -> Option<ModelEntry>` — specific model
  - `resolve_alias(org_id, alias) -> Option<String>` — alias → model_id
  - `get_pricing(org_id, model_id) -> PricingInfo` — cost per 1K tokens
- [ ] `ModelEntry` struct with: model_id, model_name, provider_config_id, provider_name, aliases, pricing, capabilities, status
- [ ] `PricingInfo` struct with: input_cost_per_1k, output_cost_per_1k
- [ ] `Capabilities` struct: streaming, tools, vision, json_mode, max_context, max_tokens
- [ ] Redis cache for model list: `config:models:{org_id}`, TTL 10 minutes
- [ ] Cache invalidation on provider config change
- [ ] `GET /v1/models` returns aggregated model list from all providers

## Files Affected
- `crates/gateway-db/src/repos/model_registry.rs` — model registry
- `crates/gateway-db/src/models.rs` — ModelEntry, PricingInfo, Capabilities structs
- `crates/gateway-api/src/routes/models.rs` — GET /v1/models handler

## Dependencies
- TASK-0023 (provider config repo)
- TASK-0006 (Redis cache)

## Technical Notes
- Query joins provider_models with provider_configs to get provider name
- Aliases stored as TEXT[] with GIN index for fast lookup
- Pricing in NUMERIC(18,8) for precision (cents per token scale)
- Model list cached in Redis as JSON array
- On provider config change: invalidate cache + publish event
- Health status from provider health checks included in model response

## Test Requirements
- Unit test: model registry lists models with correct pricing
- Unit test: alias resolution works (e.g., "gpt-4" → "gpt-4o")
- Integration test: GET /v1/models returns OpenAI-compatible format
- Integration test: cache hit returns same data as cache miss
