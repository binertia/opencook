# TASK-0085: Implement Secrets Rotation and Master Key Management

## Objective
Build the secrets rotation framework for JWT keys and encryption master keys with zero-downtime key rotation.

## Context
Secrets must be rotatable without downtime. The gateway must support active/previous key pairs. See AUTH.md section 7 and EPICS.md Epic-17.

## Acceptance Criteria
- [x] `crates/gateway-auth/src/key_rotation.rs` — key rotation module
  - `ActiveKeyPair<T>` struct: primary key (active), optional secondary key (previous)
  - `try_both()`: tries primary, falls back to secondary on failure
  - `try_both_async()`: async version with `T: Clone`
  - `parse_master_key_pair()`: parses comma-separated hex keys
  - `parse_pem_pair()`: parses comma-separated PEM blocks
- [x] `GATEWAY_MASTER_KEY` supports comma-separated list: `key1,key2`
  - First key: active (for encryption)
  - Second key: previous (for decryption of old data)
  - Decryption: try active first, then previous
- [x] Encryption multi-key support:
  - `encrypt_with_keys()`: encrypts with primary key
  - `decrypt_with_keys()`: tries primary, then secondary
  - `AppConfig::decrypt_master()`: helper method on config
- [x] JWT key rotation support:
  - `RotatingJwtService`: primary for signing, secondary for verification
  - `verify_access()` and `verify_refresh()` try primary then secondary
  - Old tokens valid during grace period
- [x] All decrypt call sites updated:
  - Provider API key decryption (chat.rs, health_worker.rs, providers.rs)
  - Webhook secret decryption (webhooks.rs, webhook_publisher.rs)
- [x] Test fixtures updated with `master_key_previous: None`

## Technical Notes
- `GATEWAY_MASTER_KEY` format: `new_key,old_key` (both 64-char hex)
- `parse_master_key_pair()` splits on comma and validates both keys
- `ActiveKeyPair::try_both()` preserves the original error when no secondary exists
- `RotatingJwtService` only falls back to secondary on `InvalidToken`, not `TokenExpired`
