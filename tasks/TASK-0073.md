# TASK-0073: Implement Webhook Event Publisher and Retry Logic

## Objective
Build the webhook event publisher and background delivery worker with retry logic.

## Context
Events are queued via an async channel and processed by a background worker that delivers signed HTTP POSTs with exponential backoff retries. See EPICS.md Epic-15.

## Acceptance Criteria
- [x] `crates/gateway-core/src/webhook_publisher.rs` — event publisher
  - `WebhookPublisher::new()` spawns background `DeliveryWorker`
  - `publish()` queues events via async `mpsc` channel
  - `DeliveryWorker` processes events concurrently (one task per webhook)
- [x] Delivery execution:
  - Lists active webhooks subscribed to the event
  - Builds payload with `event`, `timestamp`, `delivery_id`, `data`
  - Generates HMAC-SHA256 signature via `gateway_auth::crypto::hmac_sha256_hex`
  - Sends POST with `X-Webhook-Signature` header
  - Records delivery attempt in `webhook_deliveries` table
  - Retries on failure up to `webhook.max_retries` with exponential backoff
  - Updates `last_delivered_at`, `last_failure_at`, `consecutive_failures`
- [x] Error handling:
  - Delivery timeout: 30s per attempt
  - Response body preview truncated to 200 bytes
  - Failed deliveries logged with error message

## Files Affected
- `crates/gateway-core/src/webhook_publisher.rs`

## Dependencies

## Technical Notes
- Queue capacity: 1000 events
- Max concurrent deliveries per org: 5
- Retry delay base: `webhook.retry_interval_seconds`
- Signature verification: recipient can verify with `hex(HMAC-SHA256(secret, body))`
