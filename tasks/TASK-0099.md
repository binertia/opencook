# TASK-0099: Implement End-to-End Integration Tests

## Objective
Create comprehensive end-to-end tests covering the full request lifecycle: auth → routing → provider → response → logging.

## Context
E2E tests validate the entire system works together. They use testcontainers for dependencies and mock provider servers. See EPICS.md across all epics.

## Acceptance Criteria
- [ ] `tests/e2e/chat_completion_test.rs` — full chat completion flow
  - Create API key → call /v1/chat/completions → verify response → check DB log
  - Tests: streaming, non-streaming, cache hit, cache miss, fallback
- [ ] `tests/e2e/admin_flow_test.rs` — admin dashboard flow
  - Register → login → create provider → create API key → send request → view logs
- [ ] `tests/e2e/routing_test.rs` — routing engine tests
  - Create routing rules → send request → verify routed to correct provider
  - Tests: weighted, fallback, conditional strategies
- [ ] `tests/e2e/quota_test.rs` — quota enforcement
  - Set low quota → send requests → verify blocked at limit
- [ ] `tests/e2e/helpers/` — test utilities
  - `test_app.rs` — spins up full gateway with testcontainers
  - `mock_provider.rs` — mock LLM provider server
  - `fixtures.rs` — test data generators
- [ ] All E2E tests run in CI (< 10 minutes total)

## Technical Notes

- Use `httptest` or `wiremock` for mock provider servers
- Test app: full Axum server on random port with test config
- Each test: fresh database (migrations run before each test)
- Use `tokio::test` for async tests
- Parallelize tests where possible (different databases)
- CI: E2E tests run after unit tests pass
