# TASK-0065: Implement Circuit Breaker Pattern

## Objective
Build the circuit breaker that marks providers unhealthy after 5 consecutive failures and attempts recovery after 60 seconds.

## Context
Circuit breaker prevents cascading failures by temporarily disabling unhealthy providers. See ARCHITECTURE.md section 4.1 and EPICS.md Epic-13.

## Acceptance Criteria
- [ ] `crates/gateway-providers/src/circuit_breaker.rs` — circuit breaker
  - `CircuitBreaker` struct with state machine: Closed → Open → HalfOpen → Closed
  - Opens after 5 consecutive failures
  - Stays Open for 60 seconds (configurable)
  - HalfOpen: allows 1 probe request to test recovery
  - If probe succeeds → Closed; if fails → Open again
- [ ] State transitions logged at info level
  - `circuit_breaker_state_changed{provider, from, to}`
- [ ] Circuit breaker state stored in Redis: `circuit:{provider_config_id}`
  - JSON: `{ state, failures, last_failure_at, opened_at }`
- [ ] Provider marked unhealthy is excluded from routing within 30 seconds
- [ ] Each failure tracked with error code and timestamp

## Files Affected

## Technical Notes
- State machine: Closed (normal), Open (failing, no requests), HalfOpen (testing)
- Track consecutive failures, not total failures
- Use `std::sync::atomic` for in-process counters
- Redis stores the authoritative state (for cross-instance awareness)
- Probe request in HalfOpen: use health check endpoint, not real request
- Use `tracing::info!` for state transitions

## Test Requirements
- Unit test: 5 failures → Open state
- Unit test: Open for 60s → HalfOpen
- Unit test: HalfOpen + success → Closed
- Unit test: HalfOpen + failure → Open again
- Integration test: unhealthy provider excluded from routing
