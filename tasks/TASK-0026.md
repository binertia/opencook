# TASK-0026: Set Up Axum HTTP Server with Middleware Stack

## Objective
Configure the Axum HTTP server with middleware composition: auth, request ID generation, body size limit, and request logging.

## Context
The gateway API is the HTTP server entry point. It composes Tower middleware for authentication, rate limiting, request logging, CORS, and body size limits. See ARCHITECTURE.md section 3.2.1 and TECH_STACK.md section 1.1.

## Acceptance Criteria
- [ ] `crates/gateway-api/src/main.rs` — server entry point
  - Binds to `0.0.0.0:{PORT}` (default 8080)
  - Graceful shutdown on SIGTERM
- [ ] `crates/gateway-api/src/router.rs` — Axum router with middleware stack:
  - `trace_layer` — request ID generation and timing
  - `cors_layer` — configurable CORS origins
  - `body_limit` — 10MB max request body
  - `auth_layer` — API key or session auth (from TASK-0015)
  - `request_logger` — structured request logging
- [ ] `crates/gateway-api/src/state.rs` — `AppState` struct holding all shared dependencies (pool, redis, config, providers)
- [ ] `GET /health` returns `{ status: "ok" }` — liveness probe
- [ ] `GET /ready` returns 200 only when DB and Redis connections are healthy
- [ ] Server starts successfully and responds to health checks

## Files Affected
- `crates/gateway-api/src/main.rs` — entry point
- `crates/gateway-api/src/router.rs` — router + middleware
- `crates/gateway-api/src/state.rs` — shared application state
- `crates/gateway-api/src/error.rs` — HTTP error responses
- `crates/gateway-api/Cargo.toml` — axum, tower, tower-http deps

## Dependencies
- TASK-0015 (API key auth middleware)
- TASK-0013 (session auth for admin routes)
- TASK-0006 (DB pool and Redis)

## Technical Notes
- Use `axum::Router` with `.layer()` for middleware composition
- Middleware order (outer to inner): CORS → body limit → trace → auth → handler
- `tower_http::trace::TraceLayer` for request ID and timing
- `tower_http::limit::RequestBodyLimitLayer` for 10MB limit
- `tower_http::cors::CorsLayer` with configurable origins via env var
- Use `Arc<AppState>` for shared state

## Test Requirements
- Integration test: server starts, `/health` returns 200
- Integration test: `/ready` returns 200 when dependencies healthy, 503 otherwise
- Integration test: request > 10MB returns 413
- Integration test: CORS preflight request succeeds for configured origins
