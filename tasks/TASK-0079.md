# TASK-0079: Implement PII Redaction in Request/Response Logging

## Objective
Build PII redaction that prevents sensitive data (API keys, personal information) from appearing in logs and error responses.

## Context
PII redaction is a security requirement. Messages and errors must not leak sensitive data. See AUTH.md section 6.1 and EPICS.md Epic-16.

## Acceptance Criteria
- [ ] `crates/gateway-observability/src/redaction.rs` — redaction engine
  - `redact_api_keys(text: &str) -> String` — replaces `sk_gw_...` with `***`
  - `redact_emails(text: &str) -> String` — replaces emails with `[EMAIL]`
  - `redact_phone_numbers(text: &str) -> String` — replaces phone numbers
  - `redact_credit_cards(text: &str) -> String` — replaces CC numbers
  - `redact_ssn(text: &str) -> String` — replaces SSN patterns
- [ ] PII scanning in request/response bodies before logging
  - Scan message content for PII patterns
  - Redact found patterns with `[REDACTED-{type}]` placeholder
- [ ] PII redaction in error responses (never leak internal details to clients)
  - Client-facing errors: generic messages only
  - Internal logs: detailed with PII redacted
- [ ] Configurable redaction levels: `none`, `keys_only`, `full` (default `full`)
  - `GATEWAY_PII_REDACTION_LEVEL` env var
- [ ] Performance: redaction < 1ms per request body (regex-based)

## Files Affected
- `crates/gateway-observability/src/redaction.rs` — redaction engine
- `crates/gateway-api/src/error.rs` — error response sanitization
- `crates/gateway-observability/src/tracing_setup.rs` — log redaction

## Dependencies
- TASK-0077 (tracing setup)

## Technical Notes
- Use `regex` crate for pattern matching
- Pre-compile regexes at startup for performance
- API key pattern: `sk_gw_[A-Za-z0-9]{38,}`
- Email pattern: standard RFC 5322 subset
- Credit card: 13-19 digit sequences with Luhn check
- SSN: `\d{3}-\d{2}-\d{4}` or `\d{9}`
- Redact in structured log fields as well as raw text

## Test Requirements
- Unit test: API key in message content is redacted
- Unit test: email in message content is redacted
- Unit test: credit card number detected and redacted
- Unit test: error response to client contains no internal details
- Performance test: redaction < 1ms for 1KB message body
