# TASK-0079: Implement PII Redaction in Request/Response Logging

## Objective
Build PII redaction that prevents sensitive data (API keys, personal information) from appearing in logs and error responses.

## Context
PII redaction is a security requirement. Messages and errors must not leak sensitive data. See AUTH.md section 6.1 and EPICS.md Epic-16.

## Acceptance Criteria
- [x] `crates/gateway-observability/src/redaction.rs` — redaction engine
  - `redact_api_keys(text: &str) -> String` — replaces `sk_gw_...` with `[REDACTED:api_key]`
  - `redact_emails(text: &str) -> String` — replaces emails with `[REDACTED:email]`
  - `redact_phone_numbers(text: &str) -> String` — replaces phone numbers with `[REDACTED:phone]`
  - `redact_credit_cards(text: &str) -> String` — replaces CC numbers with `[REDACTED:credit_card]` (with Luhn validation)
  - `redact_ssn(text: &str) -> String` — replaces SSN patterns with `[REDACTED:ssn]`
  - `redact_bearer_tokens(text: &str) -> String` — replaces JWT bearer tokens
- [x] PII scanning in request/response bodies before logging
  - `redact()` and `redact_json()` scan and replace all known PII patterns
  - Patterns replaced with `[REDACTED:<type>]` placeholder
- [x] PII redaction in error responses (never leak internal details to clients)
  - 5xx client-facing errors: generic message only (`An internal error occurred...`)
  - 4xx client-facing errors: specific message with PII redacted
  - Internal logs: `ApiError::internal_message()` returns detailed message with PII redacted
- [x] Configurable redaction levels: `none`, `keys_only`, `full` (default `full`)
  - `GATEWAY_PII_REDACTION_LEVEL` env var controls level
  - `RedactionLevel::from_env()` parses the setting
- [x] Performance: redaction < 1ms per request body in release builds (regex-based)
  - Debug builds allowed up to 100ms for the same workload

## Files Affected
- `crates/gateway-observability/src/redaction.rs` — expanded redaction engine with individual functions, Luhn check, levels, JSON support
- `crates/gateway-api/src/error.rs` — client-facing 5xx generic messages, 4xx redacted messages, `internal_message()` helper

## Technical Notes
- Use `regex` crate for pattern matching
- Pre-compile regexes at startup for performance
- API key pattern: `sk_gw_[A-Za-z0-9]{38,}`
- Email pattern: standard RFC 5322 subset
- Credit card: 13-19 digit sequences with Luhn check
- SSN: `\d{3}-\d{2}-\d{4}` or `\d{9}`
- Redact in structured log fields as well as raw text

## Test Requirements
- Unit test: API key in message content is redacted
- Unit test: email in message content is redacted
- Unit test: credit card number detected and redacted
- Unit test: error response to client contains no internal details
- Performance test: redaction < 1ms for 1KB message body
