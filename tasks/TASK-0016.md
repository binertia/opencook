# TASK-0016: Implement RBAC Permission System

## Objective
Build the role-based access control system with four roles (owner, admin, member, viewer) and a 30+ permission matrix enforced on all admin API endpoints.

## Context
RBAC controls access to dashboard functionality and admin APIs. Four roles with a permission matrix define what actions each role can perform. See AUTH.md section 4 and EPICS.md Epic-03.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/rbac.rs` — RBAC engine with `Permission` enum (30+ variants)
- [ ] `Permission` enum covers: organizations:read/write, keys:read/write, providers:read/write, routing:read/write, quotas:read/write, usage:read, users:read/write, webhooks:read/write
- [ ] `Role` enum: Owner, Admin, Member, Viewer with permission mappings
- [ ] `check_permission(role: Role, permission: Permission) -> bool` function
- [ ] Tower middleware `RequirePermission` that extracts role from AuthContext and checks permission
- [ ] RBAC middleware returns `403 insufficient_scope` for permission violations
- [ ] `GET /api/v1/auth/me` returns user's permissions list
- [ ] Organization membership query loads user's role for the org

## Files Affected
- `crates/gateway-auth/src/rbac.rs` — RBAC engine
- `crates/gateway-auth/src/models.rs` — Role, Permission enums
- `crates/gateway-auth/src/middleware.rs` — RequirePermission middleware
- `crates/gateway-db/src/repos/org_member_repo.rs` — membership queries

## Dependencies
- TASK-0013 (session auth provides user context)
- TASK-0015 (API key auth provides key context)

## Technical Notes
- Use `strum_macros::EnumString` for permission string parsing
- Permission matrix as a `match` or `HashMap<Role, Vec<Permission>>`
- Owner = all permissions; Admin = most except org deletion; Member = limited read/write; Viewer = read-only
- Middleware extracts org_id from request path and checks membership

## Test Requirements
- Unit test: each role has expected set of permissions
- Unit test: permission check returns true for allowed, false for denied
- Integration test: viewer gets 403 on POST, admin gets 403 on org delete
