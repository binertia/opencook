# TASK-0001: Initialize Rust Workspace with Root Cargo.toml

## Objective
Create the monorepo root with Rust workspace configuration linking all backend crates.

## Context
The AI Gateway is a Rust modular monolith with multiple crates (gateway-api, gateway-core, gateway-providers, gateway-cache, gateway-quota, gateway-auth, gateway-db, gateway-observability). The workspace root coordinates dependencies and build configuration. See ARCHITECTURE.md sections 3.1-3.2 and TECH_STACK.md section 1.1.

## Acceptance Criteria
- [ ] `Cargo.toml` at workspace root defines all 8 member crates
- [ ] Workspace-level dependency versions pinned for shared crates (tokio, axum, serde, sqlx, redis, tracing, reqwest, uuid, chrono)
- [ ] `.gitignore` configured for Rust build artifacts, `.env`, and IDE files
- [ ] `rust-toolchain.toml` pins Rust 1.78+ as MSRV
- [ ] Workspace compiles with `cargo check` (stub crates acceptable)

## Files Affected
- `Cargo.toml` — new workspace root file
- `rust-toolchain.toml` — Rust version pinning
- `.gitignore` — ignore patterns for Rust/Node
- `crates/*/Cargo.toml` — stub crate definitions for all 8 crates

## Dependencies
None — this is the starting point.

## Technical Notes
Use virtual workspace pattern (no `[package]` in root). Each crate gets its own `crates/<name>/Cargo.toml`. Shared deps centralized in `[workspace.dependencies]`.

## Test Requirements
- `cargo check` passes at workspace root
- All 8 crate directories exist with valid Cargo.toml files
