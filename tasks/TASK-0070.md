# TASK-0070: Implement Semantic Cache Background Maintenance

## Objective
Build background tasks for semantic cache: expired entry cleanup, embedding table vacuum, and cache statistics.

## Context
The semantic cache table grows over time. Maintenance ensures performance doesn't degrade. See EPICS.md Epic-14.

## Acceptance Criteria
- [ ] Background cleanup task (every 5 minutes):
  - `DELETE FROM query_embeddings WHERE expires_at < NOW()`
  - `VACUUM ANALYZE query_embeddings` after cleanup
- [ ] Embedding table statistics:
  - Total entries, average age, hit rate
  - Stored in Redis: `semantic_cache:stats:{org_id}`
- [ ] Maximum entries per organization: configurable (default 100,000)
  - When exceeded: delete oldest entries (LRU based on last_hit_at)
- [ ] Semantic cache metrics:
  - `semantic_cache_hit_total` counter
  - `semantic_cache_miss_total` counter
  - `semantic_cache_entries` gauge
  - `semantic_cache_embedding_latency_ms` histogram
- [ ] Admin API: `GET /api/v1/cache/semantic-stats` returns statistics

## Files Affected
- `crates/gateway-cache/src/semantic.rs` — updated with maintenance
- `crates/gateway-cache/src/metrics.rs` — semantic cache metrics
- `crates/gateway-api/src/routes/cache.rs` — semantic stats endpoint

## Dependencies
- TASK-0068 (semantic cache storage)
- TASK-0069 (semantic cache integration)

## Technical Notes
- Use `tokio::time::interval(Duration::from_secs(300))` for cleanup
- Use `tokio::spawn` for background tasks
- LRU eviction: track `last_hit_at` timestamp, delete oldest
- `VACUUM` runs in separate connection (not pool) to avoid locking
- Stats update: after each semantic cache operation
- Use `metrics` crate for Prometheus-compatible metrics

## Test Requirements
- Integration test: expired entries deleted by cleanup
- Unit test: LRU eviction when max entries exceeded
- Integration test: stats endpoint returns correct data
- Performance test: cleanup does not block queries
