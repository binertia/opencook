# TASK-0088: Create Kubernetes Deployment Manifests

## Objective
Create Kubernetes manifests for deploying the gateway: Deployment, Service, ConfigMap, Secret, HPA, and Ingress.

## Context
Kubernetes is the primary deployment target. Manifests follow best practices: resource limits, readiness/liveness probes, rolling updates. See EPICS.md Epic-18.

## Acceptance Criteria
- [x] `k8s/namespace.yaml` — gateway namespace
- [x] `k8s/deployment.yaml` — gateway Deployment
  - 2 replicas (configurable)
  - Rolling update strategy: maxSurge 1, maxUnavailable 0
  - Resource requests: 200m CPU, 256Mi memory
  - Resource limits: 1000m CPU, 512Mi memory
  - Liveness probe: `/health` every 10s
  - Readiness probe: `/ready` every 5s
  - Environment from ConfigMap + Secret
  - Security context: runAsNonRoot, readOnlyRootFilesystem, drop ALL capabilities
  - Pod anti-affinity for node spreading
- [x] `k8s/service.yaml` — ClusterIP service on port 80 → 8080 (metrics on 9090)
- [x] `k8s/configmap.yaml` — non-sensitive configuration
  - `APP_ENV=production`, `RUST_LOG=info`
- [x] `k8s/secret.yaml` — sensitive data template
  - `GATEWAY_MASTER_KEY`, `GATEWAY_JWT_PRIVATE_KEY`, `GATEWAY_JWT_PUBLIC_KEY`
  - `DATABASE_URL`, `REDIS_URL`, `GATEWAY_ALLOWED_ORIGINS`
  - Placeholder values with warnings to replace before deploy
- [x] `k8s/hpa.yaml` — Horizontal Pod Autoscaler
  - Scale 2-20 replicas based on CPU (70%) and memory (80%)
  - Scale-up: fast (100% or 4 pods per 15s)
  - Scale-down: slow (10% per 60s, 5m stabilization)
- [x] `k8s/ingress.yaml` — Ingress with TLS
  - Host: `gateway.example.com`
  - TLS secret reference + cert-manager cluster-issuer
  - Rate limiting annotations (ingress-nginx)
  - Proxy timeouts and body size limits
- [x] `k8s/poddisruptionbudget.yaml` — minAvailable 1
- [x] `k8s/kustomization.yaml` — Kustomize base for environment overlays

## Technical Notes
- Use `kubectl apply -k k8s/` or `kustomize build k8s/ | kubectl apply -f -`
- Secrets: use `stringData` with placeholder values; never commit real secrets
- HPA requires metrics-server in cluster
- Ingress assumes nginx ingress controller + cert-manager
- PodDisruptionBudget ensures minimum 1 replica during disruptions
- Anti-affinity prefers spreading across nodes
