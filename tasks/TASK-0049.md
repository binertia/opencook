# TASK-0049: Implement Organization Settings Page

## Objective
Build the organization settings page for editing org name, slug, default routing strategy, and blocked models.

## Context
Organization settings allow admins to configure the gateway behavior for their org. See API_SPEC.md section 3.1 and EPICS.md Epic-09.

## Acceptance Criteria
- [ ] `frontend/src/pages/settings/OrganizationSettings.tsx` — settings page
  - Form to edit: org name, slug, billing email
  - Default routing strategy selector: quality/cost/latency/fallback
  - Blocked models multi-select (from available models)
  - Allowed providers multi-select
  - Save button with optimistic update
- [ ] `frontend/src/hooks/useOrganization.ts` — org data hook
  - `useOrganization()` → GET /api/v1/organizations/{org_id}
  - `updateOrganization(data)` → PUT /api/v1/organizations/{org_id}
- [ ] Settings form validation with Zod
  - Name: 1-128 chars, required
  - Slug: lowercase, alphanumeric and hyphens only
  - Email: valid email format
- [ ] Loading state while fetching, error state on failure
- [ ] Success toast on save

## Files Affected
- `frontend/src/pages/settings/OrganizationSettings.tsx` — new
- `frontend/src/hooks/useOrganization.ts` — new
- `frontend/src/components/settings/` — settings sub-components

## Dependencies
- TASK-0048 (dashboard layout)
- TASK-0047 (API client and auth)

## Technical Notes
- Use `react-hook-form` with `zodResolver` for form validation
- Use shadcn/ui `Form`, `Input`, `Select`, `MultiSelect` components
- Optimistic update: update UI immediately, rollback on error
- Use `@tanstack/react-query` `useMutation` for updates
- Fetch available models for blocked_models selector from model registry API

## Test Requirements
- Form loads with current org data
- Validation rejects invalid slug (uppercase, spaces)
- Save sends correct PUT request
- Success toast shown on save
- Error state shown on API failure
