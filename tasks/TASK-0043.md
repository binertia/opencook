# TASK-0043: Implement Usage Aggregation Pipeline

## Objective
Build the background worker that aggregates request logs into `usage_records` with hourly/daily/monthly periods.

## Context
Usage aggregation enables fast analytics queries. Raw request logs are aggregated periodically into pre-computed usage_records. See DATABASE.md section 2.9 and EPICS.md Epic-08.

## Acceptance Criteria
- [ ] `crates/gateway-quota/src/aggregator.rs` — usage aggregation worker
  - Runs every 60 seconds as background task
  - Aggregates requests from last completed hour
  - `INSERT INTO usage_records ... ON CONFLICT DO UPDATE`
- [ ] Aggregation includes:
  - request_count, request_success, request_error
  - prompt_tokens, completion_tokens, total_tokens
  - input_cost, output_cost, total_cost
  - latency_ms_p50, p90, p99, avg (computed from request latencies)
  - cache_hits, cache_misses
- [ ] Unique constraint prevents double-counting:
  - `(org_id, api_key_id, provider_config_id, provider_model_id, period, period_start)`
- [ ] Updates `requests.aggregated_at` timestamp after processing
- [ ] Handles partition boundaries correctly
- [ ] Graceful shutdown: finishes current batch before exiting

## Files Affected

- `crates/gateway-quota/src/lib.rs` — module export
- `crates/gateway-db/src/repos/usage_repo.rs` — usage records CRUD

## Technical Notes
- Use `tokio::time::interval(Duration::from_secs(60))` for periodic runs
- Aggregation query uses `date_trunc('hour', created_at)` for grouping
- Only aggregate rows where `aggregated_at IS NULL`
- Latency percentiles: use PostgreSQL `percentile_cont` or approximate in Rust
- Cost saved by cache: tracked separately in `cost_saved_cents_total` metric
- Use `ON CONFLICT DO UPDATE` for idempotent aggregation

## Test Requirements
- Unit test: aggregation produces correct counts and sums
- Unit test: double-run does not double-count (idempotent)
- Integration test: requests in DB → aggregated into usage_records
- Integration test: latency percentiles calculated correctly
- Performance test: aggregation of 10K requests completes in < 5 seconds
