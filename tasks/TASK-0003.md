# TASK-0003: Set Up CI/CD Pipeline with GitHub Actions

## Objective
Configure GitHub Actions workflows for testing, linting, security auditing, and frontend building on every PR and push to main.

## Context
CI must ensure code quality for a Rust + TypeScript monorepo: cargo test, cargo clippy, cargo audit, frontend build, and formatting checks. See EPICS.md Epic-01 acceptance criteria and TECH_STACK.md backend/frontend decisions.

## Acceptance Criteria
- [ ] `.github/workflows/ci.yml` runs on every PR and push to main
- [ ] Job 1: `cargo test` with PostgreSQL and Redis services (use service containers)
- [ ] Job 2: `cargo clippy -- -D warnings` (zero warnings allowed)
- [ ] Job 3: `cargo audit` with `--deny warnings` (blocks on critical advisories)
- [ ] Job 4: `cargo fmt --check`
- [ ] Job 5: Frontend `npm run build` (or `pnpm build`) succeeds
- [ ] Job 6: Frontend type check (`tsc --noEmit`) passes
- [ ] CI badge added to README.md

## Files Affected
- `.github/workflows/ci.yml` — CI workflow definition
- `.github/workflows/release.yml` — release workflow (future use)
- `README.md` — CI badge

## Dependencies
- TASK-0001 (workspace must exist)

## Technical Notes
- Use `dtolnay/rust-action` for Rust toolchain setup
- Use `actions/setup-node` for frontend
- Cache cargo registry and target with `Swatinem/rust-cache`
- Use service containers for postgres (16-alpine) and redis (7.2-alpine) in test job
- Set `DATABASE_URL` and `REDIS_URL` env vars pointing to service containers

## Test Requirements
- Workflow syntax validated (can use `act` locally or push to test branch)
- All 6 jobs have clear pass/fail criteria
