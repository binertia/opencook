# TASK-0031: Implement Routing Rule Data Model and Repository

## Objective
Build the routing rule repository and data structures for priority-ordered rule evaluation with JSONB conditions and targets.

## Context
Routing rules determine which provider handles each request. Rules are evaluated in priority order with model matching, strategy selection, and health-aware provider selection. See DATABASE.md section 2.6 and EPICS.md Epic-06.

## Acceptance Criteria
- [ ] `crates/gateway-db/src/repos/routing_repo.rs` — routing rule CRUD
  - `create_rule(org_id, rule) -> Rule` — create new rule
  - `list_rules(org_id) -> Vec<Rule>` — list all rules for org
  - `get_active_rules(org_id, model) -> Vec<Rule>` — rules matching model, sorted by priority
  - `update_rule(org_id, rule_id, update) -> Rule` — partial update
  - `delete_rule(org_id, rule_id)` — soft delete
- [ ] `Rule` struct: id, name, strategy (single/fallback/weighted/conditional), priority, match_model, conditions (JSONB), targets (JSONB), timeout_ms, retries, status
- [ ] `Target` struct: provider_config_id, model_id, weight (for weighted strategy)
- [ ] Redis cache for active rules: `config:routing:{org_id}`, TTL 60s
- [ ] Cache invalidation on rule change
- [ ] Admin API: `GET/POST/PUT/DELETE /api/v1/routing-rules`

## Files Affected

## Technical Notes
- Rules ordered by `priority ASC` (lower number = higher priority)
- `match_model IS NULL` means wildcard (matches any model)
- `conditions` JSONB supports: min_context_length, require_streaming, require_tools, etc.
- `targets` JSONB: ordered array of provider targets for fallback strategy
- Use partial index `idx_routing_rules_org_priority` for fast active rule lookup
