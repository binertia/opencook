# TASK-0021: Implement OpenAI Provider Adapter

## Objective
Implement the OpenAI adapter as the reference Provider implementation with full request/response transformation.

## Context
The OpenAI adapter is pass-through (canonical format already matches OpenAI), but must handle streaming, error responses, and health checks. See ARCHITECTURE.md section 3.2.3 and EPICS.md Epic-04.

## Acceptance Criteria
- [ ] `crates/gateway-providers/src/openai.rs` — OpenAI adapter implementing `Provider` trait
- [ ] Forwards chat completion requests to `https://api.openai.com/v1/chat/completions`
- [ ] Sets `Authorization: Bearer {api_key}` header from encrypted config
- [ ] Transforms OpenAI response errors into gateway error envelope format
- [ ] Streaming: uses SSE format, forwards chunks transparently
- [ ] Health check: makes lightweight request to `/v1/models` or `/v1/chat/completions` with minimal payload
- [ ] Supports all OpenAI models: gpt-4o, gpt-4o-mini, gpt-4-turbo, etc.
- [ ] Configurable base URL (for Azure OpenAI and proxies)
- [ ] Timeout configured per-provider (default 30s)

## Files Affected
- `crates/gateway-providers/src/openai.rs` — OpenAI adapter
- `crates/gateway-providers/src/http_client.rs` — shared HTTP client wrapper
- `crates/gateway-providers/src/error.rs` — provider error types

## Dependencies
- TASK-0020 (Provider trait and canonical types)
- TASK-0008 (provider_configs and provider_models tables)

## Technical Notes
- Use `reqwest::Client` with connection pooling
- Request/response transforms are identity (pass-through) for OpenAI but still explicit functions
- Error mapping: OpenAI error JSON → `ProviderError` → gateway error envelope
- Streaming uses `reqwest::Response::bytes_stream()` → SSE events
- Model list fetched from DB (provider_models table), not from OpenAI API
- Store `api_key` encrypted; decrypt with `GATEWAY_MASTER_KEY` env var

## Test Requirements
- Unit test with `httptest` mock server: chat completion request forwarded correctly
- Unit test: OpenAI error response transformed to correct gateway error
- Unit test: streaming response produces valid SSE events
- Integration test: health check returns appropriate status for mock endpoints
