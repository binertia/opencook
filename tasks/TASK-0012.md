# TASK-0012: Implement Password Hashing and User Registration

## Objective
Build the password hashing module with Argon2id and user registration flow that creates a user and their organization in a single transaction.

## Context
Dashboard users authenticate with email/password. Passwords are hashed with Argon2id (OWASP recommended). Registration creates both a user and their organization atomically. See AUTH.md sections 3.2-3.3 and DATABASE.md section 2.2.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/password.rs` — Argon2id hasher with `hash_password()`, `verify_password()`, `needs_rehash()` functions
- [ ] Password validation enforces: min 12 chars, max 128, at least 1 uppercase, 1 lowercase, 1 digit, 1 special character
- [ ] `crates/gateway-auth/src/register.rs` — registration handler that validates input, hashes password, creates user + org in DB transaction
- [ ] Registration returns `201 Created` with `{ user_id, org_id, status: "pending" }` (no auto-login)
- [ ] Duplicate email returns generic error (no enumeration): "Registration failed"
- [ ] Password hashing parameters: time_cost=3, memory_cost=65536 (64MB), parallelism=4

## Files Affected
- `crates/gateway-auth/src/lib.rs` — crate root, module declarations
- `crates/gateway-auth/src/password.rs` — Argon2id password hashing
- `crates/gateway-auth/src/register.rs` — registration logic
- `crates/gateway-auth/src/error.rs` — auth error types
- `crates/gateway-auth/Cargo.toml` — argon2, password-hash deps
- `crates/gateway-db/src/models.rs` — user/organization Rust models

## Dependencies
- TASK-0007 (organizations and users tables must exist)

## Technical Notes
- Use `argon2` crate with `Argon2id` variant
- Use `PasswordHash`, `SaltString` from `password-hash` crate
- Generate salt with `OsRng` (CSPRNG)
- Registration transaction: INSERT user → INSERT org → INSERT org_member with owner role

## Test Requirements
- Unit test: hash + verify round-trip
- Unit test: verify wrong password fails
- Unit test: password validation rejects weak passwords (< 12 chars, no uppercase, etc.)
- Integration test: registration creates user and org, duplicate email handled
