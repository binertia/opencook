# TASK-0008: Create API Keys, Provider Configs, and Models Migrations (0004-0006)

## Objective
Write migrations 0004-0006 for api_keys, provider_configs, and provider_models tables with their respective indexes.

## Context
API keys are SHA-256 hashed and scoped to organizations. Provider configs store encrypted API keys (AES-256-GCM). Provider models define available models per provider with pricing and capabilities. See DATABASE.md sections 2.3-2.5.

## Acceptance Criteria
- [ ] Migration `0004_create_api_keys.sql` creates api_keys table with all columns, indexes (uk_api_keys_key_hash, idx_api_keys_org_id, idx_api_keys_key_prefix), and trigger
- [ ] Migration `0005_create_provider_configs.sql` creates provider_configs with provider_kind enum, indexes (uk_provider_configs_org_name, idx_provider_configs_org_id), and trigger
- [ ] Migration `0006_create_provider_models.sql` creates provider_models table with indexes (uk_provider_models_provider_model, idx_provider_models_org_id, idx_provider_models_alias GIN), and trigger
- [ ] All migrations run in order without errors
- [ ] Enums are properly created before tables that reference them

## Files Affected
- `migrations/0004_create_api_keys.sql` — new
- `migrations/0005_create_provider_configs.sql` — new
- `migrations/0006_create_provider_models.sql` — new

## Dependencies

## Technical Notes
- `api_key_enc` in provider_configs is BYTEA (encrypted at application layer)
- `provider_kind` enum covers: openai, anthropic, azure_openai, google_gemini, cohere, mistral, groq, custom, bedrock
- `aliases` on provider_models uses TEXT[] with GIN index for fast routing lookups
- All partial indexes include `WHERE deleted_at IS NULL`
