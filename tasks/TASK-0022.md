# TASK-0022: Implement Anthropic, Gemini, and Ollama Adapters

## Objective
Implement provider adapters for Anthropic Claude, Google Gemini, and Ollama (local models).

## Context
Each provider has a unique API format. Adapters transform canonical OpenAI requests to provider-native format and responses back to OpenAI format. See ARCHITECTURE.md section 3.2.3 and EPICS.md Epic-04 (Anthropic), ROADMAP.md Phase 2.

## Acceptance Criteria
- [ ] `crates/gateway-providers/src/anthropic.rs` — Anthropic Claude adapter
  - Maps `messages` to Claude's `messages` format
  - Maps `model` to Claude model ID
  - `max_tokens` is required for Claude (inject default if not provided)
  - Transforms Claude response to OpenAI format
- [ ] `crates/gateway-providers/src/gemini.rs` — Google Gemini adapter
  - Converts to Gemini's `contents` format
  - Handles system instructions via `systemInstruction` field
  - Transforms Gemini response to OpenAI format
- [ ] `crates/gateway-providers/src/ollama.rs` — Ollama adapter
  - Converts to Ollama's `/api/chat` format
  - Maps model to local model name
  - Supports local/lan base URLs
- [ ] Factory updated to construct all 4 adapter types
- [ ] Each adapter has test fixtures covering all request shapes

## Technical Notes
- Temperature, top_p, max_tokens mapped where possible
- Unsupported parameters dropped with warning logged via tracing
- Each adapter implements its own request/response transform functions
- Use comprehensive test fixtures with real API response samples
- Handle streaming formats specific to each provider
- For Anthropic: system message → `system` field (not in messages array)
- For Gemini: messages → `contents` array with `role`/`parts`
