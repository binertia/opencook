# TASK-0094: Implement Quality and Balanced Routing Strategies

## Objective
Complete the routing strategy set with quality routing (best model) and balanced routing (weighted combination of cost, latency, and quality).

## Context
Quality routing prioritizes the best model regardless of cost. Balanced routing optimizes across multiple dimensions. See EPICS.md Epic-19.

## Acceptance Criteria
- [x] Quality routing strategy:
  - `gateway-core/src/strategies/quality.rs`
  - Selects best model variant (e.g., GPT-4o over GPT-4o-mini)
  - Uses model capability scores
  - Ignores cost, considers latency only for SLA compliance
- [x] Balanced routing strategy:
  - `gateway-core/src/strategies/balanced.rs`
  - Combines cost, latency, and quality into a composite score
  - Weights configurable per organization (default: cost 0.4, latency 0.4, quality 0.2)
  - Score: `weight_cost * norm_cost + weight_latency * norm_latency + weight_quality * norm_quality`
  - Selects provider with highest composite score
- [x] Strategy selection:
  - Per-organization default in `organizations.settings`
  - Per-request override via `X-Routing-Strategy` header
  - Strategy validation: reject unknown strategies
- [x] A/B testing framework (basic):
  - Randomly split traffic between two strategies
  - Track metrics per strategy variant
  - Configurable split percentage
- [x] Strategy effectiveness metrics:
  - Cost per 1K tokens per strategy
  - Latency p50 per strategy
  - Error rate per strategy

## Implementation Summary

### `gateway-core/src/strategies/quality.rs`
- Hardcoded `model_quality_score()` for 20+ models (0.0–1.0 scale)
- `QualityCandidate` — wraps `Target` with latency
- `select_best_quality()` — filters by SLA, sorts by quality desc, tiebreaks by latency
- `build_quality_fallback_chain()` — ordered by quality

### `gateway-core/src/strategies/balanced.rs`
- `BalancedCandidate` — wraps `Target` with cost, latency, token estimates
- `BalancedWeights` — configurable weights with validation (must sum to ~1.0)
- `select_balanced()` — normalizes each dimension to [0,1], inverts cost/latency, computes weighted sum
- `build_balanced_fallback_chain()` — ordered by composite score
- Normalization: `norm = 1.0 - (value / max_value)` for cost/latency, `norm = quality / max_quality` for quality

### `gateway-core/src/strategies/ab_test.rs`
- `Variant` — A/B enum
- `assign_variant()` — consistent hash using `std::hash::DefaultHasher` + (request_id, org_id)
- `StrategyConfig` — org-level default strategy + A/B test config
- `resolve_strategy()` — priority: header override → A/B variant → org default
- `is_valid_strategy()` — validates against known strategies

### `gateway-observability/src/metrics.rs`
- `record_strategy_cost()` — `gateway_strategy_cost_per_1k` histogram
- `record_strategy_latency()` — `gateway_strategy_latency_ms` histogram
- `record_strategy_error()` — `gateway_strategy_error_total` counter
- `record_strategy_routed()` — `gateway_strategy_routed_total` counter

### `gateway-core/src/strategies.rs`
