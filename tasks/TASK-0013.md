# TASK-0013: Implement JWT Session Authentication (Login/Logout/Refresh)

## Objective
Build the session authentication system using RS256-signed JWTs with 15-minute access tokens and 7-day rotating refresh tokens stored in httpOnly cookies.

## Context
System B authentication for dashboard users. Uses JWT access tokens (short-lived) + refresh tokens (long-lived). RS256 allows key rotation without invalidating existing tokens. See AUTH.md section 3.4 and API_SPEC.md section 4.2.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/jwt.rs` — JWT encode/decode with RS256, claims validation
- [ ] `crates/gateway-auth/src/session.rs` — login handler: validate credentials, issue access + refresh tokens
- [ ] Refresh token rotates on each use (old invalidated, new issued)
- [ ] `POST /api/v1/auth/login` returns `{ access_token, refresh_token, token_type: "Bearer", expires_in: 900 }`
- [ ] `POST /api/v1/auth/refresh` accepts refresh token, returns new pair
- [ ] `POST /api/v1/auth/logout` invalidates current session
- [ ] `GET /api/v1/auth/me` returns current user profile with permissions
- [ ] JWT keys loaded from `GATEWAY_JWT_PRIVATE_KEY` and `GATEWAY_JWT_PUBLIC_KEY` env vars (PEM format)

## Files Affected
- `crates/gateway-auth/src/jwt.rs` — JWT signing and verification
- `crates/gateway-auth/src/session.rs` — login, logout, refresh logic
- `crates/gateway-auth/src/models.rs` — session data structures (LoginRequest, LoginResponse)
- `crates/gateway-api/src/routes/auth.rs` — HTTP route handlers for auth endpoints

## Dependencies
- TASK-0012 (password hashing and user model)
- TASK-0011 (sessions table for refresh token storage)

## Technical Notes
- Use `jsonwebtoken` crate with `Algorithm::RS256`
- Access token expiry: 15 minutes (900 seconds)
- Refresh token expiry: 7 days (604800 seconds)
- Include `jti` claim for token revocation
- Session table stores refresh token hash (SHA-256), not plaintext
- httpOnly cookie flag set on token responses

## Test Requirements
- Unit test: JWT sign + verify round-trip
- Unit test: expired token rejected
- Unit test: tampered token rejected
- Integration test: login with valid credentials succeeds, invalid fails
- Integration test: refresh token rotation works, reused old refresh token rejected
