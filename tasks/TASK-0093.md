# TASK-0093: Implement Provider Latency Tracking and Latency-Based Routing

## Objective
Build latency-based routing that selects providers with the lowest p50 latency, with real-time latency tracking.

## Context
Latency-based routing improves response times by directing traffic to the fastest providers. See EPICS.md Epic-19.

## Acceptance Criteria
- [x] Latency tracking per provider:
  - Store last 100 latency measurements per provider in Redis
  - Use Redis list (circular buffer via LPUSH + LTRIM)
  - Compute p50, p90, p99 from stored measurements
- [x] Latency-based routing strategy:
  - `gateway-core/src/strategies/latency.rs`
  - Selects provider with lowest p50 latency that supports the model
  - Requires minimum sample size (10 measurements) before using
  - Falls back to random selection if insufficient data
- [x] Latency SLAs:
  - Configurable per organization: `latency_sla_ms` (default 5000)
  - Providers exceeding SLA penalized in routing score (1.5x penalty)
  - `X-Gateway-Latency-Sla` header on responses (default 5000ms)
- [x] Latency metrics:
  - `gateway_provider_latency_ms` histogram per provider
  - `gateway_routing_latency_ms` histogram for routing decision time
- [x] EMA (exponential moving average) for latency smoothing:
  - `ema = alpha * new_sample + (1 - alpha) * old_ema`
  - `alpha = 0.3`

## Implementation Summary

### `gateway-core/src/latency_tracker.rs`
- `record_latency()` — stores raw measurement in Redis list (LPUSH + LTRIM to 100) and updates EMA
- `get_latency_stats()` — fetches list, computes p50/p90/p99 percentiles, returns EMA
- `LatencyStats` — sample count, p50, p90, p99, EMA with `has_enough_samples()` check
- Keys: `latency:{org}:{provider}:{model}` for list, `latency:ema:{org}:{provider}:{model}` for EMA

### `gateway-core/src/strategies/latency.rs`
- `LatencyCandidate` — wraps `Target` with `LatencyStats`
- `select_lowest_latency()` — filters by min samples, sorts by routing score (p50 * penalty)
- `build_latency_fallback_chain()` — returns viable candidates ordered by latency
- SLA penalty: `score = p50 * 1.5` if p50 > SLA, else `score = p50`
