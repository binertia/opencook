# TASK-0093: Implement Provider Latency Tracking and Latency-Based Routing

## Objective
Build latency-based routing that selects providers with the lowest p50 latency, with real-time latency tracking.

## Context
Latency-based routing improves response times by directing traffic to the fastest providers. See EPICS.md Epic-19.

## Acceptance Criteria
- [ ] Latency tracking per provider:
  - Store last 100 latency measurements per provider in Redis
  - Use Redis sorted set or circular buffer
  - Compute p50, p90, p99 from stored measurements
- [ ] Latency-based routing strategy:
  - `gateway-core/src/strategies/latency.rs`
  - Selects provider with lowest p50 latency that supports the model
  - Requires minimum sample size (10 measurements) before using
  - Falls back to random selection if insufficient data
- [ ] Latency SLAs:
  - Configurable per organization: `latency_sla_ms` (default 5000)
  - Providers exceeding SLA penalized in routing score
  - `X-Gateway-Latency-Sla` header on responses
- [ ] Latency metrics:
  - `gateway_provider_latency_ms` histogram per provider
  - `gateway_routing_latency_ms` histogram for routing decision time
- [ ] EMA (exponential moving average) for latency smoothing:
  - `ema = alpha * new_sample + (1 - alpha) * old_ema`
  - `alpha = 0.3` (configurable)

## Files Affected
- `crates/gateway-core/src/strategies/latency.rs` — latency routing
- `crates/gateway-observability/src/latency_tracker.rs` — latency tracking
- `crates/gateway-providers/src/latency_buffer.rs` — circular buffer

## Technical Notes
- Use Redis list (`LPUSH` + `LTRIM` to 100) for circular buffer
- Use `redis.pipeline()` for efficient batch operations
- EMA computation in Rust (not in Redis)
- Latency penalty: `score = p50 * penalty_factor` where penalty > 1 for SLA violations
- Sample size requirement: need 10 samples before latency-based selection
- Store latency per model per provider (not just per provider)

## Test Requirements
- Unit test: lowest latency provider selected
- Unit test: insufficient samples → fallback to random
- Unit test: EMA smoothing reduces noise
- Integration test: latency routing improves p50 over random
