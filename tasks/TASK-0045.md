# TASK-0045: Implement Quota and Budget Admin API

## Objective
Build the admin API for managing quota rules and viewing usage/budget status.

## Context
Admins need to configure quotas, view current usage, and set budget caps. See API_SPEC.md section 3.6 and EPICS.md Epic-08.

## Acceptance Criteria
- [ ] `GET /api/v1/organizations/{org_id}/quotas` — list quota rules
- [ ] `POST /api/v1/organizations/{org_id}/quotas` — create quota rule
  - Fields: name, type (token_limit/cost_limit/request_limit/rate_limit), scope, limit, window, action, alert_threshold_percent
- [ ] `GET /api/v1/organizations/{org_id}/quotas/{quota_id}` — single quota
- [ ] `PUT /api/v1/organizations/{org_id}/quotas/{quota_id}` — update quota
- [ ] `DELETE /api/v1/organizations/{org_id}/quotas/{quota_id}` — delete quota
- [ ] `GET /api/v1/organizations/{org_id}/usage` — usage data with filtering
  - Query params: start_time, end_time, granularity, group_by (model/provider/api_key)
- [ ] `GET /api/v1/organizations/{org_id}/costs` — cost breakdown
  - By provider, by model, over time
- [ ] Budget cap configuration UI support (frontend data)

## Files Affected
- `crates/gateway-api/src/routes/quotas.rs` — quota admin routes
- `crates/gateway-api/src/routes/usage.rs` — usage analytics routes
- `crates/gateway-db/src/repos/quota_repo.rs` — updated with queries

## Dependencies
- TASK-0042 (quota engine)
- TASK-0043 (usage aggregation)
- TASK-0016 (RBAC)

## Technical Notes
- Use `chrono` for time range parsing (ISO 8601)
- Usage data served from `usage_records` (pre-aggregated) not raw `requests`
- Granularity: 1 minute, 1 hour, 1 day, 7 days, 1 month
- Group by: minute, hour, day, model, provider, api_key
- Cost accuracy: within 1% of sum of `usage_records.total_cost`
- Use date range picker default: last 7 days

- Integration test: date range filtering works correctly
