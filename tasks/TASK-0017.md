# TASK-0017: Implement Account Lockout and Password Reset

## Objective
Implement account lockout after 5 failed login attempts (30-minute lock) and secure password reset via token-based email flow.

## Context
Security controls for dashboard authentication. Account lockout prevents brute force. Password reset uses secure tokens sent via configurable SMTP. See AUTH.md sections 3.4 and 7.

## Acceptance Criteria
- [x] Failed login counter increments in `users.failed_login_attempts` on each failed attempt
- [x] Account locks after 5 consecutive failures for 30 minutes (`users.locked_until`)
- [x] Locked account returns `423 Locked` with `locked_until` timestamp
- [x] `POST /api/v1/auth/forgot-password` accepts email, generates reset token (32-byte random), stores in Redis with 1-hour TTL
- [x] `POST /api/v1/auth/reset-password` accepts token + new password, validates token, updates password, clears all sessions
- [x] Password reset token is single-use (deleted from Redis after use)
- [x] Successful login resets `failed_login_attempts` to 0
- [x] Login rate-limited: max 10 attempts per email per hour

## Technical Notes
- `redis.setex("password_reset:{token}", 3600, user_id)` for token storage
- Token generated with `rand::thread_rng()` (32 bytes → 64 hex chars)
- Email configuration via `GATEWAY_SMTP_HOST`, `GATEWAY_SMTP_PORT`, `GATEWAY_SMTP_USER`, `GATEWAY_SMTP_PASSWORD`, `GATEWAY_SMTP_FROM` env vars
- `lettre` crate used for SMTP email sending (async, TLS via rustls)
- New password must not match old password (checked with `verify_password` before hashing)
- Account unlocks automatically when `locked_until` expires; `failed_login_attempts` resets on successful login
- `forgot-password` returns generic success even if email not found to prevent user enumeration

## Security & Edge Cases Handled
1. **Brute force protection**: 5 failed attempts → 30-minute lock; per-email rate limit of 10/hour via Redis
2. **User enumeration prevention**: `forgot-password` returns identical success response whether email exists or not
3. **Token security**: 256-bit random token stored in Redis with 1-hour TTL; single-use (deleted after use)
4. **Password history**: Reset rejects new password if it matches the old hash
5. **Audit logging**: Failed logins logged as `SecurityViolation`; password resets logged as `Update`
6. **Lockout transparency**: 423 response includes `locked_until` timestamp so client can show countdown
7. **Auto-recovery**: Expired locks are silently ignored on next login attempt; counter resets on success
8. **Email optional**: If SMTP not configured, tokens are still generated and logged; email sending fails gracefully
