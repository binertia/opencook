# TASK-0007: Create Organizations and Users Migrations (0001-0003)

## Objective
Write SQL migrations 0001 through 0003 for PostgreSQL extensions, organizations table, and users table with indexes.

## Context
The `organizations` table is the tenant root. The `users` table holds dashboard login users. Both must have UUID primary keys, soft-delete via `deleted_at`, and `updated_at` triggers. See DATABASE.md sections 2.1, 2.2, and 6.2.

## Acceptance Criteria
- [ ] Migration `0001_create_extensions.sql` enables pgcrypto, pg_uuidv7 extensions
- [ ] Migration `0002_create_organizations.sql` creates organizations table with all columns, indexes (uk_organizations_slug, idx_organizations_status), and trigger
- [ ] Migration `0003_create_users.sql` creates users table with FK to organizations, indexes (uk_users_org_email, idx_users_org_id), and trigger
- [ ] All migrations run successfully in order via `sqlx migrate run`
- [ ] Rollback (`sqlx migrate revert`) works for each migration
- [ ] `fn_update_timestamp()` trigger function created

## Files Affected
- `migrations/0001_create_extensions.sql` — new
- `migrations/0002_create_organizations.sql` — new
- `migrations/0003_create_users.sql` — new
- `crates/gateway-db/src/migrations.rs` — migration runner helper

## Dependencies
- TASK-0006 (migration framework and pool)

## Technical Notes
- Use `BEGIN; ... COMMIT;` in each migration for atomicity
- Partial indexes include `WHERE deleted_at IS NULL` for soft-delete support
- `uk_users_org_email` is a composite unique index on `(org_id, email)` scoped to active records
- Include `ON DELETE CASCADE` on `org_id` FK in users table

## Test Requirements
- Each migration applies cleanly on fresh database
- Revert + re-apply cycle succeeds for each migration
- Verify all columns, indexes, and triggers exist after applying
