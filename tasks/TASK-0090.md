# TASK-0090: Create Terraform/Helm Infrastructure Definition

## Objective
Provide infrastructure-as-code definitions for deploying the gateway on AWS/GCP/Azure with managed PostgreSQL and Redis.

## Context
Infrastructure should be reproducible and version-controlled. Terraform modules define the required AWS/GCP/Azure resources. See EPICS.md Epic-18.

## Acceptance Criteria
- [ ] `terraform/main.tf` — Terraform configuration (AWS example)
  - EKS cluster (or ECS/EKS)
  - RDS PostgreSQL 16 (db.t3.medium, multi-AZ)
  - ElastiCache Redis 7 (cache.t3.micro, cluster mode)
  - S3 bucket for static assets (optional)
  - VPC with private subnets
  - Security groups: gateway ↔ postgres, gateway ↔ redis
- [ ] `terraform/variables.tf` — configurable variables
  - region, instance sizes, replica counts
  - database password (sensitive)
- [ ] `terraform/outputs.tf` — useful outputs
  - cluster endpoint, database endpoint, Redis endpoint
- [ ] `helm/gateway/` — Helm chart
  - `Chart.yaml` — chart metadata
  - `values.yaml` — default values
  - `templates/` — Kubernetes manifests as templates
  - Configurable: replicas, resources, env vars, secrets
- [ ] `helm/gateway/values-production.yaml` — production overrides

## Files Affected

## Technical Notes
- Terraform: use modules for reusability (RDS module, ElastiCache module)
- Helm: use `helm create gateway` as starting point
- Secrets: use External Secrets Operator or AWS Secrets Manager
- Cost estimate: include approximate monthly cost in comments
- Multi-cloud: GCP and Azure variations can be added later
- Use `terraform fmt` and `terraform validate` for formatting/validation

## Test Requirements
- `terraform validate` succeeds
- `terraform plan` produces expected resources
- `helm lint gateway/` passes
- `helm template gateway/` produces valid Kubernetes YAML
