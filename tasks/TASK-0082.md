# TASK-0082: Implement Input Validation and Injection Protection

## Objective
Add comprehensive input validation using `validator` crate, sanitize all user inputs, and prevent injection attacks.

## Context
All user inputs must be validated and sanitized to prevent injection attacks, XSS, and malformed data. See AUTH.md section 6 and EPICS.md Epic-17.

## Acceptance Criteria
- [ ] `crates/gateway-api/src/validation.rs` — input validation module
  - `ValidatedJson<T>` extractor: validates deserialized JSON using `validator`
  - Returns `400` with detailed validation errors (field + message)
- [ ] All API request DTOs use `validator` derive macros:
  - `#[validate(length(min = 1, max = 128))]` for names
  - `#[validate(email)]` for email fields
  - `#[validate(url)]` for URL fields
  - `#[validate(range(min = 1, max = 10000))]` for numeric fields
- [ ] SQL injection prevention:
  - All queries use parameterized queries (sqlx `query!` / `query_as!`)
  - No string concatenation in SQL
  - Static analysis: `cargo audit` checks for SQL injection patterns
- [ ] XSS prevention:
  - No user input rendered as HTML
  - All output JSON-encoded (Axum Json response)
  - Content-Type: `application/json` on all API responses
- [ ] Request body size limit: 10MB (enforced by Tower middleware)
- [ ] Rate limiting on auth endpoints: 10 requests/minute per IP

## Files Affected
- `crates/gateway-api/src/validation.rs` — new
- `crates/gateway-api/src/extractors.rs` — ValidatedJson extractor
- `crates/gateway-api/src/routes/*.rs` — all routes updated with validation
- `crates/gateway-db/src/models.rs` — validation annotations on DTOs

## Dependencies
- TASK-0026 (Axum extractors)
- TASK-0041 (rate limiting)

## Technical Notes
- Use `validator` crate with `Validate` derive macro
- Custom validators: `validate_cidr` for IP allowlist, `validate_model_id` for model names
- Use `serde` for deserialization + `validator` for validation in one pass
- Return structured validation errors: `{ errors: [{ field, message, code }] }`
- Size limit: `tower_http::limit::RequestBodyLimitLayer::new(10 * 1024 * 1024)`

## Test Requirements
- Unit test: valid input passes validation
- Unit test: invalid email rejected
- Unit test: too-long name rejected
- Unit test: SQL injection in input does not execute
- Integration test: request body > 10MB rejected with 413
