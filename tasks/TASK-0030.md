# TASK-0030: Implement GET /v1/models and GET /health /ready Endpoints

## Objective
Complete the public API surface with the models listing endpoint and health/readiness probes.

## Context
`GET /v1/models` lists all configured models available to the organization. Health endpoints support container orchestration. See API_SPEC.md sections 2.3 and ARCHITECTURE.md section 3.2.1.

## Acceptance Criteria
- [ ] `GET /v1/models` returns OpenAI-compatible model list:
  - `{ object: "list", data: [ { id, object: "model", created, owned_by, gateway: { provider_id, capabilities, pricing, health_status, latency_p50_ms } } ] }`
  - Filterable by `?provider=` and `?capability=` query params
  - Only shows models from active providers
- [ ] `GET /health` — liveness probe:
  - Returns `{ status: "ok" }` with HTTP 200
  - Always returns 200 (even if dependencies are down)
- [ ] `GET /ready` — readiness probe:
  - Returns 200 only when DB (PostgreSQL) and Redis are reachable
  - Returns 503 with `{ status: "not_ready", reason: "..." }` if any dependency is down
  - Checks: PostgreSQL `SELECT 1`, Redis `PING`
- [ ] `GET /v1/models/{model}` returns single model detail
- [ ] Health endpoints have no auth requirement (for load balancer probes)

## Files Affected
- `crates/gateway-api/src/routes/models.rs` — model listing
- `crates/gateway-api/src/routes/health.rs` — health/ready endpoints
- `crates/gateway-api/src/router.rs` — route registration

## Dependencies
- TASK-0026 (Axum router)
- TASK-0024 (model registry)
- TASK-0025 (health check framework for model health status)

## Technical Notes
- Model list aggregates across all configured providers for the org
- Include gateway-specific metadata in `gateway` object (additive only)
- Health checks: use existing pool to run quick queries
- Ready check should timeout each dependency check at 2 seconds
- No auth on `/health` and `/ready` by design — load balancers need them

## Test Requirements
- Integration test: GET /v1/models returns list with correct shape
- Integration test: GET /v1/models?provider=openai filters correctly
- Integration test: /health returns 200 always
- Integration test: /ready returns 200 when deps healthy, 503 when PostgreSQL down
- Integration test: GET /v1/models/{model} returns 404 for unknown model
