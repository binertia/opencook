# TASK-0091: Create Database Backup and Migration Strategy

## Objective
Document and implement database backup, point-in-time recovery, and safe migration strategies.

## Context
Production databases require automated backups and tested restore procedures. Migrations must be safe and reversible. See DATABASE.md section 6 and EPICS.md Epic-18.

## Acceptance Criteria
- [x] Backup strategy document: `docs/BACKUP_STRATEGY.md`
  - Automated daily snapshots (RDS automated backups or pg_dump)
  - Point-in-time recovery enabled (7-day retention)
  - Weekly full backup to S3 (encrypted at rest)
  - Monthly test restore procedure
- [x] Migration safety:
  - All migrations backward-compatible (add columns, never remove)
  - Migrations run in transactions (atomic)
  - `IF NOT EXISTS` on all CREATE statements
  - Migration ordering enforced by filename prefix
- [x] `scripts/backup.sh` — backup script
  - `pg_dump` with `--format=custom` and compression
  - Uploads to S3 with date-based path
  - Retention: keep 30 daily, 12 weekly, 12 monthly
- [x] `scripts/restore.sh` — restore script
  - Downloads from S3, restores with `pg_restore`
  - Validates restored database (row counts, index check)
- [x] Migration rollback plan:
  - Documented rollback steps in BACKUP_STRATEGY.md
  - `sqlx migrate revert` tested in CI
- [x] Flyway/sqlx migration verification in CI:
  - Test migrations on fresh database
  - Test migrations on database at current state

## Implementation Summary

### `docs/BACKUP_STRATEGY.md`
- Covers backup strategy (daily snapshots, weekly S3 dumps, monthly test restores)
- Documents migration safety rules (3-release cycle for column drops)
- Defines RPO/RTO targets (1h / 4h for production)
- Includes restore procedures and disaster recovery playbook

### `scripts/backup.sh`
- Performs `pg_dump` with custom format and compression level 9
- Uploads to S3 with AES-256 server-side encryption
- Date-based path: `backups/gateway/<year>/<month>/<day>/gateway-<timestamp>-daily.dump.gz`
- Supports daily, weekly (Sundays), and monthly (1st of month) backups
- Retention cleanup via `aws s3api list-objects-v2`

### `scripts/restore.sh`
- Downloads backup from S3, decompresses, and runs `pg_restore`
- Supports `--validate` mode: checks index validity and prints row counts
- Uses `pg_restore --jobs=4` for parallel restore

### `.github/workflows/migrate-check.yml`
- `migrate-fresh` job: runs `sqlx migrate run` on a fresh PostgreSQL container
- `migrate-existing` job: applies base branch migrations, then PR migrations, then tests rollback
- `migration-lint` job: checks for unsafe patterns (DROP COLUMN, DROP TABLE, missing .down.sql)

### Migration Updates
- All existing `.up.sql` migrations updated to use `CREATE TABLE IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS`
- Ensures idempotency and compliance with the new safety policy
