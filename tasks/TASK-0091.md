# TASK-0091: Create Database Backup and Migration Strategy

## Objective
Document and implement database backup, point-in-time recovery, and safe migration strategies.

## Context
Production databases require automated backups and tested restore procedures. Migrations must be safe and reversible. See DATABASE.md section 6 and EPICS.md Epic-18.

## Acceptance Criteria
- [ ] Backup strategy document: `docs/BACKUP_STRATEGY.md`
  - Automated daily snapshots (RDS automated backups or pg_dump)
  - Point-in-time recovery enabled (7-day retention)
  - Weekly full backup to S3 (encrypted at rest)
  - Monthly test restore procedure
- [ ] Migration safety:
  - All migrations backward-compatible (add columns, never remove)
  - Migrations run in transactions (atomic)
  - `IF NOT EXISTS` on all CREATE statements
  - Migration ordering enforced by filename prefix
- [ ] `scripts/backup.sh` — backup script
  - `pg_dump` with `--format=custom` and compression
  - Uploads to S3 with date-based path
  - Retention: keep 30 daily, 12 weekly, 12 monthly
- [ ] `scripts/restore.sh` — restore script
  - Downloads from S3, restores with `pg_restore`
  - Validates restored database (row counts, index check)
- [ ] Migration rollback plan:
  - Documented rollback steps for each migration
  - `sqlx migrate revert` tested in staging
- [ ] Flyway/sqlx migration verification in CI:
  - Test migrations on fresh database
  - Test migrations on database at current state

## Files Affected
- `docs/BACKUP_STRATEGY.md` — backup documentation
- `scripts/backup.sh` — backup script
- `scripts/restore.sh` — restore script
- `.github/workflows/migrate-check.yml` — migration verification CI

## Dependencies
- TASK-0011 (all migrations)

## Technical Notes
- Use RDS automated backups (if on AWS) or `pg_dump` cron job
- Store backups encrypted with AES-256 (S3 server-side encryption)
- Test restore on a separate staging database monthly
- Migration compatibility: never DROP columns in same release
  - Release 1: add new column, start writing to both
  - Release 2: stop writing to old column
  - Release 3: drop old column
- `sqlx migrate run` in CI with testcontainers

## Test Requirements
- Backup script runs successfully
- Restore script produces working database
- CI migration check passes on fresh database
- CI migration check passes on existing database
