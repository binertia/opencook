# TASK-0004: Configure Linting, Formatting, and Pre-Commit Hooks

## Objective
Set up cargo fmt, cargo clippy configuration, and frontend ESLint/Prettier with pre-commit hooks via husky or lefthook.

## Context
Consistent formatting and linting across Rust and TypeScript codebases is required. The TECH_STACK.md specifies Rust 1.78+ with clippy and a React/TypeScript frontend with Vite. See EPICS.md Epic-01.

## Acceptance Criteria
- [ ] `rustfmt.toml` configured for workspace (edition 2021, max_width 100)
- [ ] `.clippy.toml` with allowed lints and denied warnings
- [ ] Frontend ESLint config (extends TypeScript and React recommended)
- [ ] Frontend Prettier config (2-space tabs, single quotes, trailing commas)
- [ ] Pre-commit hook runs `cargo fmt`, `cargo clippy`, frontend lint, and frontend format check
- [ ] CONTRIBUTING.md documents the development workflow

## Files Affected
- `rustfmt.toml` — Rust formatting config
- `.clippy.toml` — Clippy lint configuration
- `frontend/.eslintrc.cjs` — ESLint config
- `frontend/.prettierrc` — Prettier config
- `lefthook.yml` (or `.husky/`) — pre-commit hooks
- `CONTRIBUTING.md` — contributor guidelines

## Dependencies
- TASK-0001 (workspace structure)
- TASK-0003 (CI pipeline that enforces these checks)

## Technical Notes
- Use `lefthook` (Go-based, no Node dependency) or `husky` for hooks
- Clippy deny: `clippy::unwrap_used`, `clippy::expect_used` (force explicit error handling)
- Make lefthook installable via `cargo install lefthook` or `npm install`

## Test Requirements
- Intentionally introduce a formatting error; verify hook catches it
- Intentionally introduce a clippy warning; verify hook catches it
