# TASK-0059: Implement Request Logs Viewer with Filtering

## Objective
Build the request logs page with paginated table, filtering by model/provider/status, and request detail view.

## Context
Request logs provide visibility into all AI API traffic. Admins need to search, filter, and inspect individual requests. See EPICS.md Epic-09 and API_SPEC.md section 3.7.

## Acceptance Criteria
- [x] `frontend/src/pages/Requests.tsx` — request logs page
  - Table: timestamp, trace_id, model, status, tokens, cost, latency, cache hit
  - Filters: status dropdown (All/Success/Error/Cached)
  - Search by trace_id or model
  - Pagination (server-side): limit 20, offset-based
  - Sort by timestamp (default desc)
- [x] `frontend/src/components/logs/RequestDetail.tsx` — detail drawer
  - Full request: trace_id, model, status, cache status
  - Metadata: tokens, cost, latency, timing
  - Copy trace_id button
  - Error display if present
- [x] `frontend/src/hooks/useRequestLogs.ts` — logs data hook
  - `useRequestLogs(limit, offset)` → GET /v1/requests
- [x] Auto-refresh every 30 seconds (via react-query refetchInterval)
- [x] Export to CSV button (frontend CSV generation)

## Technical Notes
- Uses shadcn/ui `Table` with pagination controls
- Filters are client-side (status filter, search)
- Request detail: `Sheet` slide-out drawer from shadcn/ui
- CSV export: browser-generated, trigger download
- Color coding: green=success, red=error, purple=cached
- Backend `list_recent` fetches with limit + 1 to detect next page
