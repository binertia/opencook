# TASK-0067: Implement Health Check Background Worker

## Objective
Build the background health check worker that probes all configured providers periodically and stores results in Redis.

## Context
Health checks run every 30 seconds. Results drive routing decisions and circuit breaker state. See EPICS.md Epic-13.

## Acceptance Criteria
- [ ] `crates/gateway-core/src/health_worker.rs` — background health worker
  - Runs every 30 seconds (configurable)
  - Iterates all active providers for all organizations
  - Makes lightweight health check call per provider
  - Stores result in Redis: `health:{provider_config_id}`
  - Updates circuit breaker based on result
- [ ] Health check history stored for 24 hours
  - Redis sorted set: `health_history:{provider_config_id}`
  - Score = timestamp, value = JSON result
  - Auto-trim entries older than 24 hours
- [ ] Recovery detection:
  - When circuit breaker is HalfOpen, health check success → Closed
  - Health check failure in HalfOpen → Open
- [ ] `GET /api/v1/providers/{id}/health-history` returns last 24h of checks
- [ ] Worker logs: check start, results, state changes

## Files Affected
- `crates/gateway-core/src/health_worker.rs` — new
- `crates/gateway-core/src/background.rs` — background task scheduler
- `crates/gateway-api/src/routes/providers.rs` — health history endpoint

## Dependencies
- TASK-0065 (circuit breaker)
- TASK-0025 (health check framework)
- TASK-0006 (Redis)

## Technical Notes
- Use `tokio::time::interval(Duration::from_secs(30))` for periodic checks
- Use `tokio::task::JoinSet` for concurrent provider checks
- Health check: call adapter's `health_check()` method
- Each check should complete within 10 seconds (timeout)
- Store history as Redis sorted set with automatic trimming
- Log using `tracing::info!` for state changes, `tracing::debug!` for normal checks
