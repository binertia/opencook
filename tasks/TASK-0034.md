# TASK-0034: Implement Weighted and Conditional Routing Strategies

## Objective
Complete the routing strategy implementations with weighted load distribution and conditional rule evaluation.

## Context
Weighted routing distributes load across providers by configured weight. Conditional routing uses JSON conditions to match requests based on properties like message count, token count, or headers. See EPICS.md Epic-06.

## Acceptance Criteria
- [ ] Weighted strategy implemented in `gateway-core/src/strategies/weighted.rs`
  - Parse weights from rule targets
  - Random selection weighted by configured values
  - Statistical distribution matches weights within 5% over 1000 requests
- [ ] Conditional strategy in `gateway-core/src/strategies/conditional.rs`
  - JSON condition evaluation: `message_count > N`, `token_count < M`
  - Header conditions: `x-priority: high`
  - Combined conditions with AND/OR logic
  - Condition compilation cache (parsed once, reused)
- [ ] `StrategyFactory` that constructs appropriate strategy from rule
- [ ] Admin API validation: reject rules with invalid conditions
- [ ] Strategy metrics emitted: `routing_strategy_applied` counter by strategy type

## Files Affected
- `crates/gateway-core/src/strategies/weighted.rs` — weighted routing
- `crates/gateway-core/src/strategies/conditional.rs` — conditional routing
- `crates/gateway-core/src/strategies/mod.rs` — strategy module
- `crates/gateway-core/src/strategies/factory.rs` — strategy factory

## Dependencies
- TASK-0032 (rule evaluation engine)
- TASK-0033 (orchestrator integration)

## Technical Notes
- Use `rand::thread_rng().gen_range()` for weighted selection
- Pre-compile JSON conditions into an AST for fast evaluation
- Conditions syntax: `{ "field": "message_count", "op": "gt", "value": 10 }`
- Support nested conditions: `{ "and": [cond1, cond2] }`
- Cache compiled conditions per-rule (HashMap<rule_id, CompiledCondition>)
- Validate conditions on rule creation (not on evaluation)

## Test Requirements
- Unit test: weighted selection distributes correctly (statistical)
- Unit test: conditional rule matches message_count condition
- Unit test: combined AND condition requires both to match
- Unit test: invalid condition rejected on rule creation
- Performance test: condition evaluation < 0.1ms per rule
