# TASK-0028: Implement SSE Streaming for /v1/chat/completions

## Objective
Add streaming support to the chat completions endpoint using Server-Sent Events (SSE) format.

## Context
Streaming is essential for real-time chat UIs. The gateway must forward provider SSE streams transparently, handling client disconnects and chunk transformation. See API_SPEC.md section 8 and ARCHITECTURE.md section 4.1.

## Acceptance Criteria
- [ ] `POST /v1/chat/completions` with `stream: true` returns SSE stream (`text/event-stream`)
- [ ] Provider SSE chunks forwarded transparently with minimal latency overhead (< 5ms/chunk)
- [ ] Client disconnect (connection dropped) aborts upstream provider request within 500ms
- [ ] Final SSE chunk includes `usage` statistics when `stream_options.include_usage: true`
- [ ] Each chunk: `data: { ... }\n\n` format (OpenAI-compatible)
- [ ] Stream termination: `data: [DONE]\n\n`
- [ ] Error mid-stream sent as SSE event with `data: { "error": ... }`
- [ ] Request still logged to DB with total tokens and latency on completion

## Files Affected

## Technical Notes
- Use `axum::response::sse::Sse` with `tokio_stream::Stream` implementation
- Use `tokio::select!` to handle client disconnect (cancel token)
- Each SSE event wraps a `StreamingChunk` serialized as JSON
- Aggregate token usage across chunks for final logging
- For non-OpenAI providers: transform provider chunks to OpenAI SSE format
- Buffer size: stream chunks as they arrive (no batching for latency)
