# TASK-0058: Implement API Key Revocation and Edit

## Objective
Build the key revocation flow with confirmation and the key edit form for updating rate limits and restrictions.

## Context
Key revocation is immediate and irreversible. Rate limits and restrictions can be updated after creation. See EPICS.md Epic-11.

## Acceptance Criteria
- [ ] Revoke button on each key row:
  - Confirmation dialog with warning: "This will immediately invalidate the key"
  - Shows last used time, suggests creating new key first
  - Submit → DELETE /api/v1/organizations/{org_id}/keys/{key_id}
  - Success: key status changes to revoked, UI updates
- [ ] Edit modal for active keys:
  - Editable: name, scopes, allowed models, IP allowlist, rate limits, expiration
  - Non-editable: key prefix (display only)
  - Submit → PUT /api/v1/organizations/{org_id}/keys/{key_id}
- [ ] `frontend/src/hooks/useKeyMutations.ts` — mutation hooks
  - `revokeKey(key_id)` → DELETE
  - `updateKey(key_id, data)` → PUT
- [ ] Revoked/expired keys show as read-only (no edit)

## Files Affected
- `frontend/src/components/keys/RevokeKeyDialog.tsx` — new
- `frontend/src/components/keys/EditKeyModal.tsx` — new
- `frontend/src/hooks/useKeyMutations.ts` — new

## Dependencies
- TASK-0056 (key list page)
- TASK-0018 (key revocation backend)

## Technical Notes
- Use shadcn/ui `AlertDialog` for revoke confirmation (destructive action)
- Warning color (red) for revoke button and dialog
- Edit form reuses CreateKeyModal components with pre-filled data
- Optimistic update: status changes immediately on revoke
- On revoke error: show error toast, revert UI

## Test Requirements
- Revoke dialog shows warning and last used time
- Revoke sends DELETE request, updates UI
- Edit form pre-fills with current values
- Edit sends PUT request with correct data
- Revoked key shows as read-only (no edit button)
