# TASK-0058: Implement API Key Revocation and Edit

## Objective
Build the key revocation flow with confirmation and the key edit form for updating name, scopes, rate limits, and expiration.

## Context
Key revocation is immediate and irreversible. Rate limits and restrictions can be updated after creation. See EPICS.md Epic-11.

## Acceptance Criteria
- [x] Revoke button on each key row:
  - Confirmation dialog with warning: "This will immediately invalidate the key"
  - Shows last used time, suggests creating new key first
  - Submit → PUT /v1/api-keys/{key_id} with status: revoked
  - Success: key status changes to revoked, UI updates
- [x] Edit modal for active keys:
  - Editable: name, scopes, rate limits, expiration
  - Non-editable: key prefix (display only)
  - Submit → PUT /v1/api-keys/{key_id}
- [x] Revoked/expired keys show as read-only (no edit/revoke buttons)

## Files Affected
- `frontend/src/components/keys/RevokeKeyDialog.tsx` — new
- `frontend/src/components/keys/EditKeyModal.tsx` — new
- `frontend/src/pages/ApiKeys.tsx` — updated to use new components

## Dependencies
- TASK-0056 (key list page)
- TASK-0018 (key revocation backend)

## Technical Notes
- Uses shadcn/ui `Dialog` for revoke confirmation (destructive action)
- Warning color (red) for revoke dialog title
- Edit form reuses CreateKeyModal patterns with pre-filled data
- Uses `react-hook-form` + `zodResolver` for edit validation
- Revoked/expired keys: edit and revoke buttons hidden, delete still available
- `useUpdateApiKey` hook handles both edit and revoke mutations
