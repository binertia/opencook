# TASK-0002: Set Up Docker Compose Development Environment

## Objective
Create a `docker-compose.dev.yml` that spins up PostgreSQL 16, Redis 7, and provides service definitions for the gateway and dashboard.

## Context
The gateway requires PostgreSQL for persistent state and Redis for caching, rate limiting, and ephemeral data. The dev environment must provide hot-reload for both backend (cargo-watch) and frontend (Vite HMR). See TECH_STACK.md section 2.3 and ARCHITECTURE.md section 2.4.

## Acceptance Criteria
- [ ] `docker-compose.dev.yml` defines services: postgres, redis, backend (cargo watch), frontend (vite dev)
- [ ] PostgreSQL 16-alpine with healthcheck via `pg_isready`
- [ ] Redis 7.2-alpine with `appendonly yes` and healthcheck via `redis-cli ping`
- [ ] Named volumes for `postgres_dev_data`, `redis_dev_data`, `cargo_cache`, `target_cache`
- [ ] Backend service depends_on postgres and redis with `condition: service_healthy`
- [ ] `docker compose -f docker-compose.dev.yml up -d postgres redis` starts successfully

## Files Affected
- `docker-compose.dev.yml` — new development orchestration file
- `docker/Dockerfile.backend.dev` — development backend image
- `docker/Dockerfile.frontend.dev` — development frontend image

## Dependencies
- TASK-0001 (workspace structure must exist for backend build context)

## Technical Notes
- Use Docker Compose healthchecks for startup ordering
- Backend dev Dockerfile installs cargo-watch for hot reload
- Frontend dev Dockerfile uses Node 20 + pnpm
- Do NOT expose PostgreSQL/Redis ports externally in production compose

## Test Requirements
- `docker compose -f docker-compose.dev.yml up -d postgres redis` succeeds
- `pg_isready` against the postgres container returns true
- `redis-cli ping` against the redis container returns PONG
