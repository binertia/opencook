# TASK-0066: Implement Request Cancellation and Fallback Chain

## Objective
Build client disconnect detection that aborts upstream provider requests within 500ms, and the fallback chain that tries alternative providers when the primary fails.

## Context
When a client disconnects, the gateway must stop the upstream request to avoid wasting provider tokens. Fallback chain tries backup providers. See ARCHITECTURE.md section 4.1 and EPICS.md Epic-13.

## Acceptance Criteria
- [x] `crates/gateway-core/src/cancellation.rs` — cancellation token propagation
  - `with_cancellation`: wraps futures, returns `Cancelled` when token fires
  - `with_cancellation_and_timeout`: combines cancellation + hard timeout
  - `CancelOnDrop`: guard that cancels token when handler scope ends (client disconnect)
  - `spawn_disconnect_watcher`: background task for explicit disconnect signals
  - Aborts upstream within 500ms via `tokio::select!`
- [x] `crates/gateway-core/src/fallback.rs` — fallback chain execution
  - `execute_fallback_chain`: tries providers sequentially
  - Circuit breaker check per attempt
  - Cancellation respected — stops chain on disconnect
  - Fallback exhausted → `FallbackExhausted` with all attempts logged
  - Each attempt gets retry logic (via `retry()`)
- [x] Cancellation + fallback interaction:
  - Client disconnect during fallback → cancel current attempt
  - Don't try remaining fallback providers after disconnect
- [x] Request context includes `CancellationToken` throughout lifecycle
- [x] Handler integration:
  - `CancelOnDrop` wired in `chat.rs` non-streaming handler
  - Token passed to `orchestrate_chat_completion`
  - Retry (`RetryConfig::default()`) wrapped around each `provider.chat_completion()` call

## Technical Notes
- `CancelOnDrop` implements `Drop` → calls `token.cancel()` when handler scope ends
- This catches Axum client disconnects because the handler future is dropped
- Retry: `gateway_core::retry::retry(RetryConfig::default(), || provider.chat_completion(req))`
- Fallback inline in handler: primary → fallbacks with circuit breaker + retry per attempt
