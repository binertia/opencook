# TASK-0035: Implement Routing Admin API and Cache Invalidation

## Objective
Build the admin API for managing routing rules with validation, and implement event-driven cache invalidation for rule changes.

## Context
Admins need to create, update, and delete routing rules via the dashboard. Rule changes must propagate to the gateway within 60 seconds via cache invalidation. See API_SPEC.md section 3.5 and EPICS.md Epic-06.

## Acceptance Criteria
- [x] `GET /api/v1/routing-rules` — list all rules for org (paginated)
- [x] `POST /api/v1/routing-rules` — create rule with validation
  - Validate: name unique per org, priority in range 1-1000, valid strategy
  - Validate: all target providers exist and are active
  - Validate: conditions JSON is syntactically valid
- [x] `GET /api/v1/routing-rules/{id}` — get single rule
- [x] `PUT /api/v1/routing-rules/{id}` — update rule (partial update)
- [x] `DELETE /api/v1/routing-rules/{id}` — soft delete rule
- [x] On rule change: delete Redis cache `config:routing:{org_id}` + publish `routing:changed` event
- [x] Rule change propagates to new requests within 60 seconds
- [x] Audit log entry created for each rule CRUD operation

## Technical Notes
- Uses `validator` crate for input validation
- Uses `serde_json::Value` for conditions/targets with custom validation
- Cache invalidation: `redis.del` + `redis.publish` on `routing:changed`
- Partial update: JSONB conditions are shallow-merged; targets are replaced when provided
- RBAC enforced: `RoutingRead` for list/get, `RoutingWrite` for create/update, `RoutingDelete` for delete
- Audit log entry created for each rule CRUD operation (non-blocking, logs errors instead of failing request)
