# TASK-0005: Create README.md and GitHub Issue Templates

## Objective
Write comprehensive README.md with setup instructions, architecture overview, and GitHub issue templates for bug reports and feature requests.

## Context
The README is the first impression and onboarding tool. Per EPICS.md, a new engineer must be able to clone and run in under 30 minutes. GitHub issue templates standardize bug reports and feature requests. See TECH_STACK.md for architecture details.

## Acceptance Criteria
- [ ] README.md includes: project description, tech stack badge list, quick start (clone to first request in <10 min), architecture diagram link, configuration reference, API compatibility notes
- [ ] `.github/ISSUE_TEMPLATE/bug_report.yml` with fields: description, reproduction steps, expected vs actual behavior, environment (OS, Rust version, gateway version), logs
- [ ] `.github/ISSUE_TEMPLATE/feature_request.yml` with fields: description, use case, proposed solution, alternatives considered
- [ ] `.github/pull_request_template.md` with checklist: tests pass, docs updated, breaking changes noted, screenshot for UI changes

## Files Affected
- `README.md` — project documentation
- `.github/ISSUE_TEMPLATE/bug_report.yml` — bug report template
- `.github/ISSUE_TEMPLATE/feature_request.yml` — feature request template
- `.github/pull_request_template.md` — PR template

## Dependencies
- TASK-0001 (workspace structure must be documented)
- TASK-0002 (Docker setup must be documented)

## Technical Notes
- Keep README quick-start under 20 lines
- Link to docs/ folder for detailed architecture and API docs
- Include one-liner `curl` example for first proxied request
- Include `docker compose` quick-start path

## Test Requirements
- README renders correctly on GitHub (no broken links, proper formatting)
- Issue templates render correctly (can test via GitHub preview)
