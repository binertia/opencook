# TASK-0086: Implement CORS, CSRF Protection, and Security Audit

## Objective
Finalize CORS configuration, add CSRF protection for admin endpoints, and run a comprehensive security audit.

## Context
CORS and CSRF protect against cross-origin attacks. The security audit identifies and fixes any remaining vulnerabilities. See AUTH.md section 7 and EPICS.md Epic-17.

## Acceptance Criteria
- [ ] CORS finalization:
  - `GATEWAY_ALLOWED_ORIGINS` parsed from env var
  - Wildcard `*` not allowed in production (must specify origins)
  - Credentials allowed for admin API (cookies)
  - Preflight caching: `Access-Control-Max-Age: 86400`
- [ ] CSRF protection for admin API:
  - Double-submit cookie pattern for state-changing requests
  - `X-CSRF-Token` header required for POST/PUT/DELETE to `/api/v1/*`
  - Token generated on login, stored in httpOnly + SameSite cookie
- [ ] Security audit checklist:
  - `cargo audit` passes (no known vulnerabilities)
  - No hardcoded secrets in codebase
  - No debug endpoints in production
  - No stack traces in error responses
  - Input validation on all endpoints
  - Rate limiting on all public endpoints
- [ ] `security/audit-checklist.md` — documented security checklist
  - OWASP Top 10 mitigations mapped to gateway features
  - Secure deployment guidelines
- [ ] Static analysis: `cargo clippy` with security linting passes

## Technical Notes
- CSRF token: 32-byte random, generated on login, stored in session
- SameSite=Lax or Strict on all cookies
- CORS: use `tower_http::cors::CorsLayer::very_permissive()` only in dev
- Production: explicit origin list from env var
- `cargo audit` runs in CI: block on critical advisories
- Use `clippy::unwrap_used`, `clippy::expect_used` to force error handling

## Test Requirements
- Integration test: CSRF token missing → 403 for POST
- Integration test: CSRF token present → request succeeds
- Integration test: CORS blocked for unauthorized origin
- Integration test: `cargo audit` passes in CI
- Manual: verify no stack traces in error responses
