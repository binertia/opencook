# TASK-0077: Implement Structured Request Logging with tracing

## Objective
Set up structured request logging with OpenTelemetry-compatible `tracing` spans for every LLM API request with configurable sampling.

## Context
All LLM requests must generate trace records for debugging and monitoring. Logs are structured JSON for machine parsing. See ARCHITECTURE.md section 6.1 and EPICS.md Epic-16.

## Acceptance Criteria
- [x] `crates/gateway-observability/src/tracing_setup.rs` — tracing configuration
  - JSON formatter for production (`GATEWAY_ENV=production`), pretty for development
  - Environment filter: `RUST_LOG` env var support
  - Default level: `info` for gateway, `warn` for dependencies
- [x] Every LLM request logged with structured fields:
  - `trace_id`, `org_id`, `api_key_id`, `model_requested`, `model_routed`
  - `provider_name`, `status`, `status_code`, `error_code`
  - `latency_ms`, `prompt_tokens`, `completion_tokens`, `total_tokens`
  - `cache_hit`, `cost_usd`
  - `routing_rule_id` — field present, wired when routing layer exposes rule ID
- [x] Separate log levels:
  - `ERROR`: 5xx errors, provider failures (via `tracing::error!`)
  - `WARN`: 4xx errors, quota warnings, cache misses (via `tracing::warn!`)
  - `INFO`: successful requests, routing decisions, cache hits (via `tracing::info!`)
  - `DEBUG`: request/response body previews (via `log_body_preview` helper)
- [x] Sampling: counter-based deterministic sampling for INFO logs
  - `GATEWAY_LOG_SAMPLE_RATE` env var overrides (0.0–1.0, default 1.0)
  - ERROR/WARN always pass through
- [x] Sensitive data redacted from logs (API keys, emails, SSNs, bearer tokens)

## Technical Notes
- Use `tracing` + `tracing-subscriber` crates
- JSON format: `tracing_subscriber::fmt::layer().json()`
- Use `tracing::info_span!` for request spans with fields
- Use `tracing::instrument` attribute for automatic span creation
- Redaction: regex patterns for API keys (`sk_gw_[A-Za-z0-9]+`), emails, SSNs
- Sampling: use custom `Layer` implementation with rate limiting

## Test Requirements
- Logs are valid JSON parseable
- All required fields present in request log
- API keys redacted from log output
- Sampling reduces log volume at expected rate
