# TASK-0036: Implement Cache Key Builder and Cacheability Rules

## Objective
Build the cache key generation system (SHA-256 of normalized request) and cacheability determination logic.

## Context
Cache keys must be deterministic for identical requests. Not all requests are cacheable — rules determine which can be cached. See CACHE.md section 2.2 and EPICS.md Epic-07.

## Acceptance Criteria
- [ ] `crates/gateway-cache/src/key_builder.rs` — cache key generation
  - `build_key(request) -> CacheKey` — deterministic hash
  - Includes: model, normalized messages (canonical JSON), temperature, max_tokens, top_p, penalties, stop sequences, response format, tools, seed, logit_bias
  - SHA-256 of concatenated normalized fields
  - Sorts object keys, arrays for determinism
- [ ] `crates/gateway-cache/src/cacheable.rs` — cacheability checker
  - `is_cacheable(request) -> bool` with rules:
    - temperature must be == 0 (or absent)
    - stream must be false (unless X-Cache-Stream: true header)
    - no tools with dynamic schemas
    - no dynamic content patterns in system prompt (timestamps, UUIDs)
    - not explicitly skipped via X-Cache-No-Store header
- [ ] `CacheKey` struct: request_hash (String), model (String), org_id (Uuid)
- [ ] Cache key includes org_id prefix for tenant isolation in Redis
- [ ] Normalization handles null/optional fields consistently

## Technical Notes
- Use `sha2::Sha256` for hashing
- Use `serde_json` with sorted keys for canonical JSON
- Temperature comparison: `temperature.unwrap_or(0.0) == 0.0` for cacheable
- Dynamic content detection: regex for patterns like `{current_time}`, `{user_id}`, ISO timestamps
- Cache key format in Redis: `cache:{org_id}:{model}:{hash}`
- PII detection (basic regex for SSN, email, credit card) — skip cache if detected

## Test Requirements
- Unit test: identical requests produce identical cache keys
- Unit test: different requests produce different cache keys
- Unit test: temperature=0 request is cacheable, temperature>0 is not
- Unit test: streaming request not cacheable by default
- Unit test: request with dynamic timestamp in prompt not cacheable
