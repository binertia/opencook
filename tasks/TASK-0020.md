# TASK-0020: Define Provider Trait and Canonical Request/Response Types

## Objective
Define the `Provider` Rust trait and the canonical `ChatCompletionRequest` / `ChatCompletionResponse` types used across all provider adapters.

## Context
All LLM backends implement a common trait. Request/response types are canonical OpenAI-compatible formats that adapters transform to/from provider-native formats. See ARCHITECTURE.md section 3.2.3 and EPICS.md Epic-04.

## Acceptance Criteria
- [ ] `crates/gateway-providers/src/lib.rs` — crate root with trait definition and module declarations
- [ ] `crates/gateway-core/src/types.rs` — canonical types:
  - `ChatCompletionRequest` with model, messages (Vec<Message>), temperature, max_tokens, stream, etc.
  - `ChatCompletionResponse` with id, object, created, model, choices, usage
  - `Message` with role (system/user/assistant/tool), content, name, tool_calls
  - `StreamingChunk` for SSE stream pieces
- [ ] `crates/gateway-providers/src/traits.rs` — `Provider` trait with methods:
  - `fn name(&self) -> &str`
  - `fn supported_models(&self) -> Vec<&str>`
  - `async fn chat_completion(&self, req: ChatCompletionRequest) -> Result<...>`
  - `async fn chat_completion_stream(&self, req: ChatCompletionRequest) -> Result<SseStream>`
  - `async fn embeddings(&self, req: EmbeddingRequest) -> Result<...>`
  - `async fn health_check(&self) -> HealthStatus`
- [ ] `crates/gateway-providers/src/factory.rs` — `create_provider(config) -> Box<dyn Provider>`
- [ ] `HealthStatus` enum: Healthy, Degraded(reason), Unhealthy(reason)

## Technical Notes
- Use `async_trait` crate for the Provider trait (dynamic dispatch)
- Use `reqwest` for HTTP client in adapters
- Canonical types should mirror OpenAI API spec fields exactly
- `SseStream` type alias for `axum::response::sse::Sse<impl Stream<Item=Result<Event, ...>>>`
- Factory uses `match config.kind` to construct appropriate adapter
