# TASK-0062: Implement API Key Usage Table with Drill-Down

## Objective
Build the API key usage analytics page showing per-key usage, cost, and token consumption with drill-down capability.

## Context
Per-key attribution helps organizations track which applications/teams are spending what. See EPICS.md Epic-12.

## Acceptance Criteria
- [ ] `frontend/src/pages/analytics/KeyUsagePage.tsx` — key usage analytics
  - Table: key prefix, name, requests, tokens, cost, avg latency
  - Sortable by any column
  - Pagination (server-side)
  - Click row → drill-down: key detail with usage over time chart
- [ ] `frontend/src/components/analytics/KeyUsageTable.tsx` — sortable table
  - Server-side sorting and pagination
  - Cost column right-aligned with currency format
- [ ] `frontend/src/components/analytics/KeyDetailPanel.tsx` — drill-down panel
  - Key info: name, prefix, status, scopes
  - Usage over time: line chart (requests + cost)
  - Top models used by this key
  - Recent requests filtered by key
- [ ] Date range picker applies to all data
- [ ] Responsive: table scrollable horizontally on mobile

## Files Affected
- `frontend/src/pages/analytics/KeyUsagePage.tsx` — new
- `frontend/src/components/analytics/KeyUsageTable.tsx` — new
- `frontend/src/components/analytics/KeyDetailPanel.tsx` — new

## Dependencies
- TASK-0060 (analytics overview)
- TASK-0045 (usage API with api_key_id filter)

## Technical Notes
- Use `recharts` LineChart for usage over time
- Table sorting: send `sort_by` and `sort_order` to backend
- Pagination: limit/offset with total count from backend
- Drill-down: `Sheet` drawer from shadcn/ui
- Format: currency for cost, compact notation for large numbers

## Test Requirements
- Table renders with correct per-key data
- Sorting sends correct params to backend
- Drill-down shows key-specific charts
- Date range applies to all views
