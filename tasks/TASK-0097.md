# TASK-0097: Implement SCIM 2.0 User Provisioning

## Objective
Build SCIM 2.0 (System for Cross-domain Identity Management) endpoints for automatic user provisioning/deprovisioning from identity providers.

## Context
SCIM enables automatic user lifecycle management: when a user is added/removed in the IDP, they are automatically added/removed in the gateway. See EPICS.md Epic-20.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/scim.rs` — SCIM 2.0 implementation
  - `GET /scim/v2/Users` — list users (paginated)
  - `GET /scim/v2/Users/{id}` — get user
  - `POST /scim/v2/Users` — create user
  - `PUT /scim/v2/Users/{id}` — update user
  - `PATCH /scim/v2/Users/{id}` — partial update (activate/deactivate)
  - `DELETE /scim/v2/Users/{id}` — deactivate user (soft delete)
  - `GET /scim/v2/ServiceProviderConfig` — SP configuration
  - `GET /scim/v2/ResourceTypes` — resource types
  - `GET /scim/v2/Schemas` — schemas
- [ ] SCIM endpoints authenticated with Bearer token (per-org SCIM token)
  - `scim_tokens` table: org_id, token_hash, created_at, expires_at
  - Token generated on SSO config creation
- [ ] User mapping:
  - SCIM `userName` → gateway email
  - SCIM `name.givenName` + `name.familyName` → gateway name
  - SCIM `active` → gateway status
- [ ] Group mapping (optional):
  - SCIM groups → gateway org roles
  - `GET /scim/v2/Groups` — list groups
- [ ] Audit log entry on each SCIM operation

## Technical Notes
- Use `scim_protocol` crate or implement manually
- SCIM content type: `application/scim+json`
- Pagination: `startIndex` and `count` parameters
- Filter support: `filter=userName eq "user@example.com"`
- Soft delete on SCIM DELETE: set status to 'suspended', don't hard delete
- SCIM token: separate from API keys, stored as hash only
