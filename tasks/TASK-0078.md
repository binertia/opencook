# TASK-0078: Implement Prometheus Metrics and /metrics Endpoint

## Objective
Instrument the gateway with Prometheus-compatible metrics and expose them at `/metrics`.

## Context
Prometheus metrics enable monitoring and alerting. Key metrics include latency histograms, request counters, cache hit rates, and cost tracking. See ARCHITECTURE.md section 6.2 and EPICS.md Epic-16.

## Acceptance Criteria
- [x] `crates/gateway-observability/src/metrics.rs` — metrics registry
  - `gateway_request_duration_ms` — histogram with model/provider/status labels
  - `gateway_request_total` — counter with model/provider/status labels
  - `gateway_cache_hit_total` — counter with layer (l1/l2/semantic) label
  - `gateway_cache_miss_total` — counter
  - `gateway_tokens_total` — counter with type (input/output) and model labels
  - `gateway_cost_total` — counter with model and provider labels
  - `gateway_quota_exceeded_total` — counter with metric and scope labels
  - `gateway_provider_health` — gauge with provider and org labels
  - `gateway_rate_limited_total` — counter with key_hash label (hashed to prevent unbounded cardinality)
  - `gateway_active_connections` — gauge
- [x] `/metrics` endpoint returns Prometheus text format at same port
  - Separate metrics port (9090) can be added later via `METRICS_PORT` env var
- [x] Histogram buckets: 1ms, 5ms, 10ms, 25ms, 50ms, 100ms, 250ms, 500ms, 1s, 2.5s, 5s, 10s
- [x] All metric labels bounded (no unbounded label values) — sanitized + hashed where needed
- [x] Memory-efficient: uses `metrics-exporter-prometheus` crate
- [x] `ConnectionLayer` middleware tracks active connections via `gateway_active_connections` gauge
- [x] Semantic cache hits now emit `gateway_cache_hit_total{layer="semantic"}`

## Technical Notes
- Use `metrics` crate for emitting + `metrics-exporter-prometheus` for exposition
- Metric names prefix: `gateway_`
- Label cardinality: org_id hashed to avoid high cardinality in shared clusters
- Separate metrics port: `METRICS_PORT` env var (default 9090)
- Metrics endpoint has no auth (for Prometheus scraping)
- Use `metrics::histogram!` with appropriate bucket configuration

## Test Requirements
- `/metrics` returns valid Prometheus text format
- All expected metrics present with correct labels
- Histogram buckets defined correctly
- Metrics endpoint returns 200 without auth
