# TASK-0006: Create Database Migration Framework and Connection Pool

## Objective
Set up sqlx-cli migration infrastructure with a migration runner that executes on startup, and configure the database connection pool with tenant isolation support.

## Context
All persistent state lives in PostgreSQL 16. The migration framework (sqlx) manages schema evolution with plain SQL migrations. Connection pooling (sqlx::Pool) must enforce tenant isolation via RLS context. See DATABASE.md section 6 and TECH_STACK.md section 1.3.

## Acceptance Criteria
- [ ] `migrations/` directory created with `.keep` file
- [ ] `sqlx-cli` configured with `sqlx-data.json` for offline compilation
- [ ] Database connection pool configured in `crates/gateway-db/src/pool.rs` with min 5 / max 20 connections
- [ ] Pool includes `after_connect` hook that sets `app.org_id` for RLS context
- [ ] Migration runner trait `MigrationRunner` defined with `run_migrations()` method
- [ ] `sqlx migrate run` works against fresh PostgreSQL 16 database

## Files Affected
- `crates/gateway-db/Cargo.toml` — new crate with sqlx dependencies
- `crates/gateway-db/src/lib.rs` — crate root, re-exports pool and repo modules
- `crates/gateway-db/src/pool.rs` — connection pool with RLS context
- `crates/gateway-db/src/error.rs` — database error types
- `migrations/.keep` — migration directory marker

## Dependencies
- TASK-0001 (workspace structure)
- TASK-0002 (PostgreSQL container for local testing)

## Technical Notes
- Use `PgPoolOptions` from sqlx for pool configuration
- The `after_connect` hook must set `SET app.org_id = '00000000-0000-0000-0000-000000000000'` for default connections
- All errors should use a custom `DbError` enum derived from `thiserror`
- Enable `sqlx/runtime-tokio` and `sqlx/tls-rustls` features

## Test Requirements
- Pool creation test against testcontainer PostgreSQL
- RLS context verification: query `current_setting('app.org_id')` returns expected value
- Connection limits respected (max 20 concurrent connections)
