# TASK-0069: Integrate Semantic Cache into Request Orchestrator

## Objective
Integrate semantic cache as a layer between L1/L2 cache and provider call — check semantic cache on L2 miss before calling the LLM provider.

## Context
The semantic cache sits in the cache hierarchy: L1 → L2 → Semantic → Provider. On semantic miss, the embedding is computed and stored alongside the response. See CACHE.md section 3 and ARCHITECTURE.md section 4.1.

## Acceptance Criteria
- [ ] Orchestrator updated to check semantic cache after L1/L2 miss
  - Cache flow: L1 → L2 → Semantic → Provider → L1/L2 store + Semantic store
- [ ] On semantic hit: return cached response with `X-Cache: SEMANTIC_HIT`
- [ ] On semantic miss: call provider, generate embedding from prompt, store both
  - Embedding generated asynchronously (fire-and-forget after response)
- [ ] Semantic cache only for: temperature=0, non-streaming, no tools, no dynamic content
- [ ] Embedding generation skipped if provider response was an error
- [ ] Cost tracking: semantic hit counted as cache hit (cost=0)

## Files Affected

## Technical Notes
- Extract last user message for embedding (not full conversation)
- Use existing OpenAI adapter for embedding generation
- Embedding generation: `tokio::spawn` after response, non-blocking
- Store: embedding in pgvector, response in Redis (same as L2)
- Cache key for response: same hash as L2 cache key
- Similarity threshold: 0.97 cosine (configurable via env var)
