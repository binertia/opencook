# TASK-0056: Implement API Key List Page with Status and Usage

## Objective
Build the API key management page showing all keys with prefix, name, status, last used, and usage count.

## Context
Admins manage gateway API keys through the dashboard. The list shows key metadata without exposing full keys. See EPICS.md Epic-11.

## Acceptance Criteria
- [ ] `frontend/src/pages/keys/KeysPage.tsx` — API key list page
  - Table: key prefix, name, status (active/revoked/expired), scopes, last used, created
  - Usage column: request count and estimated cost for current period
  - Status filter: All, Active, Revoked, Expired
  - Sortable by created, last used, usage
  - Search by name or prefix
  - Pagination (server-side)
- [ ] `frontend/src/hooks/useApiKeys.ts` — API keys data hook
  - `useApiKeys(org_id, filters)` → GET /api/v1/organizations/{org_id}/keys
  - `useApiKeyUsage(key_id)` → usage stats for a key
- [ ] Each row has: revoke button (if active), edit link
- [ ] "Create Key" button opens create modal

## Files Affected
- `frontend/src/pages/keys/KeysPage.tsx` — new
- `frontend/src/hooks/useApiKeys.ts` — new

## Dependencies
- TASK-0048 (dashboard layout)
- TASK-0014 (API key generation backend)
- TASK-0047 (API client)

## Technical Notes
- Use shadcn/ui `Table` with pagination
- Status badge: green (active), red (revoked), gray (expired)
- Usage: fetch from `usage_records` filtered by `api_key_id`
- Format: `Intl.NumberFormat` for costs, relative time for "last used"
- `key_prefix` displayed as `sk_gw_aB3x...` with tooltip

## Test Requirements
- Key list renders with correct columns
- Status filter works correctly
- Sorting by created/last used works
- Pagination fetches correct page
