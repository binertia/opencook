# TASK-0044: Integrate Rate Limiting and Quota into Request Orchestrator

## Objective
Integrate rate limiting (step 3) and quota checking (step 4) into the request lifecycle middleware and orchestrator.

## Context
Rate limiting and quota checking happen before the cache check. They are critical path — any latency directly impacts request overhead. See ARCHITECTURE.md section 4.1 steps 3-4 and EPICS.md Epic-08.

## Acceptance Criteria
- [ ] Rate limit middleware applied to all LLM API routes
  - Uses API key ID as rate limit key
  - Checks both requests/minute and tokens/minute limits
  - Returns 429 with `Retry-After` header when exceeded
- [ ] Quota check integrated into orchestrator before cache check
  - Uses org_id + key_id from AuthContext
  - Estimates cost from `max_tokens × pricing`
  - Returns 403 with `quota_exceeded` when budget cap reached
  - Adds `X-Quota-Warning` header at warning threshold
- [ ] Rate limit headers returned on every response
- [ ] Quota deducted after successful request (atomic upsert)
- [ ] Cost calculated from actual token usage and stored in `requests.total_cost`
- [ ] Zero-cost for cache hits (cost=0, but still count toward request quota)

## Files Affected
- `crates/gateway-api/src/middleware/rate_limit.rs` — rate limit middleware
- `crates/gateway-core/src/orchestrator.rs` — quota check + deduct integration
- `crates/gateway-core/src/quota_middleware.rs` — quota check middleware

## Dependencies

## Technical Notes
- Rate limit check in Tower middleware (before handler)
- Quota check in orchestrator (needs request body for cost estimation)
- Post-request: quota usage incremented with actual token count
- Cost: `input_cost = prompt_tokens × input_cost_per_1k / 1000`
- Use `tokio::spawn` for post-request quota update (non-blocking)
- Deduct from both org-level and key-level quotas if configured

## Test Requirements

- Integration test: quota exceeded returns 403 with quota_exceeded
- Integration test: warning threshold adds X-Quota-Warning header
- Integration test: cache hit counts toward request quota but not cost quota
- Integration test: concurrent requests respect quota limits
