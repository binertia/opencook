# TASK-0074: Implement Quota and Budget Alert Webhooks

## Objective
Trigger webhook events for quota warnings (at 80% threshold) and budget cap reached (100%), and provider status changes.

## Context
Alert webhooks notify external systems of important events. They fire once per event, not repeatedly. See EPICS.md Epic-15.

## Acceptance Criteria
- [ ] Quota warning webhook (fires once when crossing 80%):
  - Event: `quota.warning`
  - Payload: `{ quota_id, metric, limit, current_usage, threshold_percent, org_id }`
  - Not sent again until usage drops below threshold and re-crosses
- [ ] Quota exceeded webhook (fires once at 100%):
  - Event: `quota.exceeded`
  - Payload: `{ quota_id, metric, limit, current_usage, org_id }`
  - Triggers hard block on subsequent requests
- [ ] Provider error webhook (fires once per provider transition):
  - Event: `provider.error`
  - Payload: `{ provider_config_id, provider_name, error_code, error_message, timestamp }`
- [ ] Provider recovered webhook:
  - Event: `provider.recovered`
  - Payload: `{ provider_config_id, provider_name, timestamp }`
- [ ] Request completed/failed webhooks:
  - Event: `request.completed` / `request.failed`
  - Payload: `{ trace_id, model, tokens, cost, latency, status }`
- [ ] Deduplication: same event type + resource ID not sent within 5 minutes

## Technical Notes
- Deduplication: use Redis `SETNX` with 5-minute TTL
- Key: `webhook_dedup:{event_type}:{resource_id}`
- Quota warning: check after each quota increment, fire once on threshold cross
- Provider error: fire on state transition from healthy to unhealthy
- Provider recovered: fire on state transition from unhealthy to healthy
- Request events: only sent if webhook is subscribed to these events
