# TASK-0074: Implement Quota and Budget Alert Webhooks

## Objective
Trigger webhook deliveries when quota warnings or budget thresholds are reached.

## Context
Quota/budget alerts notify external systems when usage approaches or exceeds limits. See EPICS.md Epic-15.

## Acceptance Criteria
- [x] Quota warning publishes `quota.warning` event via webhook
  - Triggered in `quota_middleware` when `QuotaResult::Warning`
  - Data: `{ threshold, remaining }`
- [x] Quota exceeded publishes `quota.exceeded` event via webhook
  - Triggered in `quota_middleware` when `QuotaResult::Exceeded`
  - Data: `{ metric, limit }`
- [x] `WebhookPublisher` wired into `AppState`
  - Initialized in `AppState::from_env()`
  - Available to all handlers and middleware
- [x] Publishing is fire-and-forget (`tokio::spawn`)
  - Does not block request processing
  - Delivery failures do not affect the API response

## Files Affected
- `crates/gateway-api/src/state.rs` — added `webhook_publisher` field
- `crates/gateway-api/src/middleware/quota.rs` — added `publish_quota_webhook()`

## Dependencies
- TASK-0073 (webhook event publisher)
- TASK-0042 (quota engine)
- TASK-0067 (health check worker)

## Technical Notes
- `publish_quota_webhook()` helper spawns a background task to publish
- Only publishes if `state.webhook_publisher` is `Some`
- Uses `gateway_db::WebhookEvent::QuotaWarning` and `QuotaExceeded`

## Test Requirements
- Integration test: quota warning triggers webhook delivery
- Integration test: quota exceeded triggers webhook delivery
- Unit test: publishing is non-blocking
