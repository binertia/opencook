# TASK-0015: Implement API Key Validation Middleware

## Objective
Build the API key validation middleware that extracts and validates `Authorization: Bearer sk-gw-...` headers on every LLM API request with Redis caching.

## Context
Every incoming LLM API request must be authenticated. API key validation must complete in < 1ms p99 (cache hit) or < 5ms (cache miss). Validation checks format, hash lookup, expiry, and IP allowlist. See AUTH.md section 2.4 and EPICS.md Epic-03.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/api_key_validator.rs` — key extraction and validation
- [ ] Tower middleware layer in `crates/gateway-api/src/middleware/api_key_auth.rs`
- [ ] Redis cache: `auth:apikey:{key_hash}` → serialized key data, 5-minute TTL
- [ ] Cache miss → DB lookup → cache population
- [ ] Validation includes: format check, hash match, status=active, expiry check, IP allowlist check
- [ ] Valid key produces `AuthContext` attached to request extensions
- [ ] Invalid key returns `401 authentication_error` with no internal state leakage
- [ ] Constant-time hash comparison to prevent timing attacks
- [ ] Dummy hash lookup performed on miss to maintain constant time

## Files Affected
- `crates/gateway-auth/src/api_key_validator.rs` — validation logic
- `crates/gateway-auth/src/models.rs` — AuthContext struct
- `crates/gateway-api/src/middleware/api_key_auth.rs` — Tower middleware
- `crates/gateway-api/src/middleware/mod.rs` — middleware module

## Dependencies
- TASK-0014 (API key generation and storage)
- TASK-0006 (connection pool and Redis)

## Technical Notes
- Use `subtle` crate for constant-time comparison
- AuthContext contains: org_id, key_id, user_id (optional), permissions Vec, rate_limit_tier
- Always perform a dummy hash query on cache miss to prevent timing attacks
- Extract client IP from `x-forwarded-for` or connection info
- Cache invalidation on key revocation: delete Redis key + publish event

## Test Requirements
- Unit test: valid key passes validation
- Unit test: revoked key returns 401
- Unit test: expired key returns 401
- Unit test: wrong IP returns 403 (ip_not_allowed)
- Unit test: timing difference between valid and invalid keys < 1ms
- Integration test: cache hit vs cache miss latency measured
