# TASK-0075: Implement Webhook Management UI

## Objective
Build the webhook management page with list, create, edit, test, and delivery log views.

## Context
Admins manage webhook subscriptions and monitor delivery status through the dashboard. See EPICS.md Epic-15.

## Acceptance Criteria
- [ ] `frontend/src/pages/webhooks/WebhooksPage.tsx` — webhook list
  - Table: URL, events subscribed, status (active/inactive), delivery success rate
  - Toggle active/inactive status
  - Delete button with confirmation
  - Create button → opens create modal
- [ ] `frontend/src/components/webhooks/CreateWebhookModal.tsx` — creation
  - URL input (validated format)
  - Event selection: checkboxes for all event types
  - Secret key display (shown once)
  - Test webhook button (sends test event)
- [ ] `frontend/src/components/webhooks/WebhookDeliveryLog.tsx` — delivery history
  - Table: timestamp, event, status (success/failed), response code, latency
  - Request/response preview (expandable)
  - Retry button for failed deliveries
- [ ] `frontend/src/hooks/useWebhooks.ts` — webhooks data hook
  - `useWebhooks()` → list
  - `createWebhook()`, `updateWebhook()`, `deleteWebhook()`, `testWebhook()`

## Files Affected
- `frontend/src/pages/webhooks/WebhooksPage.tsx` — new
- `frontend/src/components/webhooks/CreateWebhookModal.tsx` — new
- `frontend/src/components/webhooks/WebhookDeliveryLog.tsx` — new
- `frontend/src/hooks/useWebhooks.ts` — new

## Technical Notes
- Use shadcn/ui `Table`, `Dialog`, `Checkbox`, `Switch` components
- Secret key: display in monospace with copy button, warning about one-time display
- Test webhook: POST to URL with test payload, show response
- Delivery status: green check for success, red X for failed
- Event selection: group by category (requests, quotas, providers)

## Test Requirements
- Webhook list renders with correct data
- Create form validates URL format
- Secret key shown on creation
- Test webhook sends request and shows result
- Delivery log shows attempt history
