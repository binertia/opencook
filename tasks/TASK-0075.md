# TASK-0075: Implement Webhook Management UI

## Objective
Build the frontend webhooks management page with CRUD operations, status toggling, and delivery log viewer.

## Context
Admins need to configure webhooks, view delivery history, and retry failed deliveries. See EPICS.md Epic-15.

## Acceptance Criteria
- [x] `frontend/src/pages/webhooks/WebhooksPage.tsx` — webhook list
  - Table: name, URL, events, status, last delivered, failures
  - Toggle active/inactive status inline
  - Delete webhook with confirmation dialog
  - Click row to view delivery log
- [x] `frontend/src/components/webhooks/CreateWebhookModal.tsx` — create form
  - Name, URL, events (multi-select), custom headers (JSON)
  - Max retries, retry interval, timeout
  - Secret displayed once after creation
- [x] `frontend/src/components/webhooks/WebhookDeliveryLog.tsx` — delivery history
  - Table: timestamp, event, status, response status, error
  - Retry button for failed deliveries
- [x] `frontend/src/hooks/useWebhooks.ts` — data hooks
  - `useWebhooks`, `useCreateWebhook`, `useUpdateWebhook`, `useDeleteWebhook`
  - `useWebhookDeliveries`, `useRetryDelivery`

## Files Affected
- `frontend/src/pages/webhooks/WebhooksPage.tsx`
- `frontend/src/components/webhooks/CreateWebhookModal.tsx`
- `frontend/src/components/webhooks/WebhookDeliveryLog.tsx`
- `frontend/src/hooks/useWebhooks.ts`

## Technical Notes
- Event labels mapped to human-readable names
- Status badges: active (default), inactive (secondary), failing (destructive)
- Delivery status: delivered, failed, pending
- Uses shadcn/ui Table, Dialog, Badge, Switch, Skeleton

## Test Requirements
- Table renders webhook list correctly
- Create form submits with correct payload
- Toggle status updates via mutation
