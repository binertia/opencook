# TASK-0023: Implement Provider Config Encryption and Storage

## Objective
Build AES-256-GCM encryption for provider API keys at rest and the provider configuration repository layer.

## Context
Provider API keys are sensitive credentials stored in PostgreSQL. They must be encrypted with AES-256-GCM derived from `GATEWAY_MASTER_KEY`. See DATABASE.md section 2.4 and ARCHITECTURE.md section 3.2.3.

## Acceptance Criteria
- [x] `crates/gateway-auth/src/crypto.rs` — AES-256-GCM encryption/decryption module
  - `encrypt(plaintext: &str, master_key: &[u8]) -> Result<Vec<u8>>`
  - `decrypt(ciphertext: &[u8], master_key: &[u8]) -> Result<String>`
  - Uses AES-256-GCM with random nonce prepended to ciphertext
- [x] `crates/gateway-db/src/repos/provider_config_repo.rs` — CRUD for provider_configs
  - `create`, `get_by_id`, `list_by_org`, `update`, `soft_delete`
  - All queries include `WHERE org_id = $1`
  - Stores `api_key_enc` as encrypted bytes
- [x] `crates/gateway-db/src/repos/model_registry.rs` — CRUD for provider_models
  - `create_model`, `get_model`, `update_pricing`, `delete_models_by_provider`
- [x] Master key loaded from `GATEWAY_MASTER_KEY` env var (32 bytes, hex-encoded)
- [x] Gateway fails to start if master key is not set or wrong length **in production**
  - Dev fallback: generates random key with loud warning

## Technical Notes
- `aes_gcm` crate with `Aes256Gcm` cipher
- Nonce: 96-bit (12 bytes), randomly generated per encryption, prepended to ciphertext
- Master key: 256-bit (32 bytes), hex-encoded in env var, parsed at startup via `parse_master_key`
- **Production**: `GATEWAY_MASTER_KEY` missing → panic at startup (fail-closed)
- **Development**: random key generated with loud warning; encryption will NOT survive restarts
- Store encrypted key as BYTEA/BLOB in PostgreSQL/SQLite
- Decrypt only when needed (in route handler before sending to provider adapter)

## Security & Edge Cases Handled
1. **Fail-closed in production**: Missing `GATEWAY_MASTER_KEY` causes immediate panic in production environment
2. **Invalid key format**: Non-hex or wrong-length master key causes panic with clear error message
3. **Random nonce**: Each encryption uses a fresh random nonce; same plaintext produces different ciphertexts
4. **Tamper detection**: AES-GCM authentication tag verifies ciphertext integrity; tampered data fails decryption
5. **Wrong key detection**: Decrypting with incorrect master key fails authentication tag verification
6. **Dev ergonomics**: Development mode auto-generates a random key so the gateway starts without configuration
