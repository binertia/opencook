# TASK-0023: Implement Provider Config Encryption and Storage

## Objective
Build AES-256-GCM encryption for provider API keys at rest and the provider configuration repository layer.

## Context
Provider API keys are sensitive credentials stored in PostgreSQL. They must be encrypted with AES-256-GCM derived from `GATEWAY_MASTER_KEY`. See DATABASE.md section 2.4 and ARCHITECTURE.md section 3.2.3.

## Acceptance Criteria
- [ ] `crates/gateway-auth/src/crypto.rs` — AES-256-GCM encryption/decryption module
  - `encrypt(plaintext: &str, master_key: &[u8]) -> Result<Vec<u8>>`
  - `decrypt(ciphertext: &[u8], master_key: &[u8]) -> Result<String>`
  - Uses AES-256-GCM with random nonce prepended to ciphertext
- [ ] `crates/gateway-db/src/repos/provider_config_repo.rs` — CRUD for provider_configs
  - `create`, `get_by_id`, `list_by_org`, `update`, `soft_delete`
  - All queries include `WHERE org_id = $1`
  - Encrypts `api_key` field before storing
  - Decrypts `api_key` field on retrieval
- [ ] `crates/gateway-db/src/repos/provider_model_repo.rs` — CRUD for provider_models
- [ ] Master key loaded from `GATEWAY_MASTER_KEY` env var (32 bytes, hex-encoded)
- [ ] Gateway fails to start if master key is not set or wrong length

## Technical Notes
- Use `aes_gcm` crate with `Aes256Gcm` cipher
- Nonce: 96-bit (12 bytes), randomly generated per encryption, prepended to ciphertext
- Master key: 256-bit (32 bytes), hex-encoded in env var, parsed at startup
- Fail closed: if `GATEWAY_MASTER_KEY` not set → panic at startup
- Store encrypted key as BYTEA in PostgreSQL
- Decrypt only when needed (in adapter, not in repo) for security

## Test Requirements
- Unit test: encrypt + decrypt round-trip produces original plaintext
- Unit test: tampered ciphertext fails decryption
- Unit test: wrong master key fails decryption
- Integration test: store config with encrypted key, retrieve and decrypt correctly
- Integration test: missing GATEWAY_MASTER_KEY causes startup failure
