# TASK-0092: Implement Per-Model Pricing and Cost-Optimized Routing

## Objective
Build cost-optimized routing that selects the cheapest capable provider for each model, and implement per-model pricing management.

## Context
Cost optimization is a key value proposition. The gateway routes to the cheapest provider that supports the requested model. See ROADMAP.md Phase 4 and EPICS.md Epic-19.

## Acceptance Criteria
- [ ] Cost-optimized routing strategy:
  - `gateway-core/src/strategies/cost_optimized.rs`
  - Selects cheapest provider that: supports model, is healthy, meets latency SLA
  - Cost = `input_cost_per_1k * prompt_tokens + output_cost_per_1k * completion_tokens`
  - For prompt-only routing: estimates cost from `max_tokens`
- [ ] Per-model pricing in provider_models table:
  - `input_cost_per_1k` and `output_cost_per_1k` per model per provider
  - Admin API to update pricing: `PUT /api/v1/providers/{id}/models/{model}/pricing`
  - Pricing validated: positive numbers, max $1/token
- [ ] Cost comparison in routing:
  - For each provider supporting the model: estimate cost
  - Select provider with minimum estimated cost
  - If tie: select by health score (healthier first)
  - If tie: select by latency (lower p50 first)
- [ ] Cost routing configurable per organization:
  - Default routing strategy in `organizations.settings`
  - Options: quality (best provider), cost (cheapest), latency (fastest), balanced

## Files Affected

## Technical Notes
- Cost estimation: use `max_tokens` from request for output cost estimate
- Actual cost computed post-request from actual token usage
- Pricing updates: invalidate model cache
- Cost routing metrics: `routing_cost_savings_total` counter
- SLA: configurable max latency per org (default 10s)

## Test Requirements
- Unit test: cheapest provider selected for model
- Unit test: unhealthy provider skipped even if cheapest
- Unit test: cost estimation accuracy
- Integration test: cost routing reduces total spend vs random routing
