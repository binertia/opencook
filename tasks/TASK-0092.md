# TASK-0092: Implement Per-Model Pricing and Cost-Optimized Routing

## Objective
Build cost-optimized routing that selects the cheapest capable provider for each model, and implement per-model pricing management.

## Context
Cost optimization is a key value proposition. The gateway routes to the cheapest provider that supports the requested model. See ROADMAP.md Phase 4 and EPICS.md Epic-19.

## Acceptance Criteria
- [x] Cost-optimized routing strategy:
  - `gateway-core/src/strategies/cost_optimized.rs`
  - Selects cheapest provider that: supports model, is healthy, meets latency SLA
  - Cost = `input_cost_per_1k * prompt_tokens + output_cost_per_1k * completion_tokens`
  - For prompt-only routing: estimates cost from `max_tokens`
- [x] Per-model pricing in provider_models table:
  - `input_cost_per_1k` and `output_cost_per_1k` per model per provider
  - Admin API to update pricing: `PUT /api/v1/providers/{id}/models/{model}/pricing`
  - Pricing validated: positive numbers, max $1/token
- [x] Cost comparison in routing:
  - For each provider supporting the model: estimate cost
  - Select provider with minimum estimated cost
  - If tie: select by health score (healthier first)
  - If tie: select by latency (lower p50 first)
- [x] Cost routing configurable per organization:
  - Default routing strategy in `organizations.settings`
  - Options: quality (best provider), cost (cheapest), latency (fastest), balanced

## Implementation Summary

### `gateway-core/src/strategies/cost_optimized.rs`
- `ProviderCandidate` — wraps `Target` with pricing, health, and latency
- `HealthStatus` — Healthy / Degraded / Unhealthy with scoring for tie-breaking
- `estimate_cost()` — computes cost from token estimates and per-1k pricing
- `select_cheapest()` — filters by health/latency, sorts by cost, then health, then latency
- `build_cost_fallback_chain()` — returns all viable candidates ordered by cost

### `gateway-core/src/strategies.rs`
- Added `pub mod cost_optimized`
- Updated `build_decision()` to recognize `"cost"` strategy (falls back to first target when no runtime pricing context is available; callers with pricing data should use `cost_optimized` directly)

### `gateway-db/src/repos/model_registry.rs`
- Added `update_pricing()` — validates pricing bounds (0 ≤ price ≤ $1.00 per 1k tokens) and updates the DB

### `gateway-api/src/routes/models.rs`
- Added `UpdatePricingRequest` DTO with `input_cost_per_1k` and `output_cost_per_1k`
- Added `update_pricing()` handler — requires owner/admin role, returns 204 on success

### `gateway-api/src/router.rs`
- Added route: `PUT /v1/providers/:provider_id/models/:model_id/pricing`
